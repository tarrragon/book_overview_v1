## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

### CB 缺漏補正

Context Bundle 不變式表僅列 6 個 bundle（core x2、page x2、platform x1、ux Theme x1），但 ticket `what` 欄位與 title 皆稱「7 個」。經比對 `docs/spec/user-experience/domain-map.md` §3，確認 user-experience domain 實際有 5 個 bundle，CB 漏列第 7 個：**Notification & Accessibility**（NotificationService、AccessibilityService，`src/background/domains/user-experience/services/`，不變式：「通知顯示後可手動關閉；無障礙色彩對比度 >= 4.5」）。已一併補上對應測試。

### 各 bundle 測試產出與 src API 對齊情況

先讀取所有目標 src 檔案確認 API 存在後才寫測試，逐 bundle 記錄如下：

| Domain | Bundle | 測試檔 | src API 對齊情況 |
|---|---|---|---|
| core | Enum System | `tests/unit/core/enums/enum-system.test.js` | **CB 假設與實際 src 有落差**：`src/core/enums/index.js` 解構匯出 `isValidOperationStatus` / `isValidErrorType` / `isValidSeverity` / `isValidMessageType` / `isValidPriority` / `isValidLogLevel` 等驗證函式，但對應的 `OperationStatus.js` / `ErrorTypes.js` / `MessageTypes.js` / `LogLevel.js` 皆未實作這些函式，destructure 結果為 `undefined`。CB 不變式「驗證函式對非法值回傳 false」在目前 src 狀態下不成立（函式根本不存在，非回傳 false）。測試改為：(1) 驗證各列舉值集合不重複（不變式前半，可測）；(2) 驗證 `LogLevel` 實際存在的 `compareLogLevels`/`shouldLog` 行為；(3) 明確鎖定 `isValid*` 系列函式現況為 `undefined`，避免未來誤用。已提 Spawn Request 追蹤此 API 缺口（見下方 Spawn Requests）。 |
| core | Migration Tools | `tests/unit/core/migration/MigrationValidator.test.js`, `tests/unit/core/migration/MigrationProgressTracker.test.js` | API 存在。`MigrationValidator.validateFile()` 內部呼叫真實 `fs.readFile` / `execSync`（ESLint、Jest），測試改用 `jest.spyOn` 取代 `_validateByType` 驗證編排的私有方法，測試 overall 結果聚合邏輯（PASS/WARNING/FAIL 優先序），並直接測試不涉及 I/O 的 `validateErrorCodeMapping()`。`MigrationProgressTracker` 的 `registerMigrationItem`/`updateItemStatus` 會呼叫 `_saveState()` 寫入真實檔案系統，測試以 `jest.mock('fs')` 取代，驗證 `getProgress().percentage` 隨完成項目數增加單調遞增且落在 0-100%。 |
| page | Navigation | `tests/unit/background/domains/page/services/navigation-service.test.js` | **CB 不變式後半與實際 src 不符**：CB 稱「MutationObserver 正確清理」，但 `NavigationService`（`src/background/domains/page/services/navigation-service.js`）並無 MutationObserver，改用 `chrome.webNavigation` 事件監聽器（`onBeforeNavigate`/`onCommitted`/`onHistoryStateUpdated` 等）偵測 URL 變更（含 SPA hash，經 `onHistoryStateUpdated`）。MutationObserver 實際位於 `src/content/detectors/page-detector.js`（歸屬 Page Detection bundle，非 Navigation bundle，`docs/spec/page/domain-map.md` §4.1 亦有此邊界說明）。測試改為驗證 NavigationService 實際 API：URL 變更事件（含 hash）正確寫入導航歷史、非目標網域不追蹤、`stop()` 正確清除 `webNavigationListeners`。 |
| page | Permission Management | `tests/unit/background/domains/page/services/permission-management-service.test.js` | **CB 不變式與實際 src 不符**：CB 稱「必要權限缺失時回傳明確錯誤」，但 `PermissionManagementService` 並無此處拋出 Error 的實作，而是以 `hasEssentialPermissions()`（布林）與 `getMissingPermissions()`（缺失清單，含 config 描述）提供明確、可程式化判讀的缺失資訊供上層決策。測試對齊此實際行為。 |
| platform | Platform Switcher | `tests/unit/background/domains/platform/services/platform-switcher-service.test.js` | API 存在且與 CB 不變式完全對齊：`switchToPlatform()` 透過 `validateSwitchRequest()` 檢查 `platformRegistry.getPlatform()`，已註冊且 active 平台切換成功、未註冊或非 active 平台切換失敗（回傳 `success:false` + 明確 error 訊息）。測試過程中發現：若保留預設 `switchConfig.autoFallback = true`，驗證失敗情境下 `attemptFallback()` 會反覆重試同一個必然失敗的目標平台，形成無窮遞迴（測試曾因此觸發 heap OOM），故測試中對非 fallback 情境明確停用 `autoFallback`（測試層修正，非 src bug，因該遞迴僅在特定 mock 組合下才會發生；仍已提 Spawn Request 追蹤，見下方）。 |
| user-experience | Theme & Personalization | `tests/unit/background/domains/user-experience/services/theme-management-service.test.js` | API 存在。測試涵蓋 `setTheme('dark')` 後已註冊提供者收到含 `colors`/`mode` 的 `updateTheme` 呼叫（對應「CSS 變數更新」）、`persistThemePreference`/`loadUserThemePreference` 透過共用 `storageService` 模擬跨服務實例（模擬重啟）偏好保留。 |
| user-experience | Notification & Accessibility | `tests/unit/background/domains/user-experience/services/notification-service.test.js`, `tests/unit/background/domains/user-experience/services/accessibility-service.test.js` | API 存在。`NotificationService.showNotification()` + `clearNotification()` 驗證「通知顯示後可手動關閉」。`AccessibilityService.wcagRules.contrast.requirement === 4.5` 驗證對比度門檻設定，`validateAccessibilityCompliance()` 驗證合規報告含對比度規則且通過（注意：`checkContrastCompliance()` 目前為簡化實作，恆回傳 `true`，非本票範圍）。 |
