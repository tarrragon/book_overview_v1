## Task Summary

依 domain-bundle-mapping 方法論，從各 domain spec 的 FR 反推 bundle 邊界，界定依賴方向 DAG，產出 domain map。本專案有 9 個 domain（core/data-mgmt/extraction/messaging/page/platform/sync/system/ux），已有 src/background/domains/ 實作結構

## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

本專案有 9 個 domain（core / data-management / extraction / messaging / page / platform / synchronization / system / user-experience），已有 src/background/domains/ 實作結構和 domain-architecture-comparison-report（與 APP 對照），但缺正式 domain map。domain 知識分散在 spec 和 src 各處，無權威的 bundle 邊界與依賴方向 DAG 定義。

### 影響範圍

- docs/spec/{domain}/ 下所有 9 個 domain 子目錄
- 影響後續 TDD 派發切分、測試策略與架構決策依據

### 相關 Error Pattern

無已知相關錯誤模式。

---

## 重現實驗結果

### 實驗方法

1. 逐 domain 讀取 docs/spec/{domain}/ 下所有 spec 檔案，提取 FR 清單
2. 參考 src/background/domains/ 實作結構驗證依賴方向（grep import 鏈）
3. 依 domain-bundle-mapping 方法論三步反推 bundle 邊界
4. 用 check_domain_coverage.py 驗證每個 spec 的 FR 是否被 domain-map.md 覆蓋

### 實驗執行

- 讀取全部 9 個 domain spec（SPEC-001 至 SPEC-009）+ SPEC-STORAGE-ISOLATION + SPEC-010
- grep 驗證 import 鏈：extraction → core（ErrorCodes）; page → core; messaging → core; user-experience → core（ErrorCodes, COLORS）; data-management → core
- 依方法論分類：aggregate root / kernel / read-model / supporting VO / domain service / saga / 非 domain（infra / cross-cutting / presentation）
- 8 個 spec 全部通過 check_domain_coverage.py 覆蓋檢核

### 實驗發現

**已驗證事實**：
- 9 個 domain 間依賴形成合法 DAG（無環）
- core 為最底層（零依賴），被所有其他 domain 依賴
- data-management 含兩個獨立 aggregate（Book + Tag），by-id 參照
- extraction 透過事件（EXTRACTION.COMPLETED）與 data-management 解耦，不直接 import storage
- synchronization 在 V1 無獨立 src 目錄，僅有協議規格（與 APP 架構不同）
- user-experience 大部分 bundle 屬 presentation/cross-cutting，唯 SearchEngine 為 domain read-model

---

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

產出 9 個 domain-map.md（每個 domain 子目錄各一），內容涵蓋：

1. **分層與依賴方向 DAG**：core（零依賴）→ messaging / platform / system / data-management → page / extraction / synchronization / user-experience
2. **Bundle 界定表**：每個 domain 的 bundle 含分類（aggregate / kernel / read-model / supporting VO / domain service / saga / 非 domain）、納入概念、排除、目標路徑、測試層
3. **Bundle 不變式清單**：每個 bundle 的業務規則不變式，可直接轉為 unit test
4. **FR → Bundle 覆蓋對照**：逐一對照 spec FR 到 bundle，全部通過 check_domain_coverage.py
5. **邊界決策**：含 extraction-storage 事件解耦、Book-Tag 雙 aggregate by-id 參照、synchronization 協議 vs 實作分離等
6. **技術債觀察**：各 domain 已記錄觀察到的技術債
