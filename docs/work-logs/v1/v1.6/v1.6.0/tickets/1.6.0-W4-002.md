## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因（從 W3-007 ANA 確認）

event-coordinator.js L556-574 正規化 map callback 只做 tags/readingStatus/applyDefaults，**不處理 ID**：
- 不映射 `bookId` → `platformBookId`
- 不為 `id` 為 falsy 的書目生成 UUID

各 adapter ID 欄位名不統一：
| Adapter | 欄位名 | 值來源 |
|---------|--------|--------|
| readmoo | `id` | stable-id-generator（4 策略 cascade，fallback 保證 truthy） |
| kobo | `bookId` | DOM 提取 ebook slug |
| books-com-tw | `bookId` | `info.item`（可為空字串 `''`） |

### 實作策略

在 L566 `const withStatus = { ...b, tags, readingStatus }` 之後、`applyDefaults()` 之前，新增 ID 正規化邏輯：

1. **`bookId` → `platformBookId` 映射**：若 `b.bookId` 存在且 truthy，寫入 `platformBookId`
2. **`id` 自動生成**：若合併後 `id` 仍為 falsy，用 `crypto.randomUUID()` 生成（Chrome SW 環境原生支援）
3. **保留既有 `id`**：readmoo 的 `id` 由 stable-id-generator 產生，不覆蓋

順序理由：ID 正規化必須在 `applyDefaults()` 之前——`BookSchemaV2` 的 `id` 定義為 `required: true` 但無 `default`，applyDefaults 不會補 `id`。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
在 `src/background/events/event-coordinator.js` L566-576（`withStatus` 構建後、`applyDefaults()` 前）新增 ID 正規化邏輯：

1. `bookId` truthy 時映射為 `platformBookId`（kobo/books-com-tw adapter 欄位）
2. 合併後 `id` 仍為 falsy 時，用 `globalThis.crypto.randomUUID()` 生成
3. readmoo 既有 truthy `id`（stable-id-generator 產生）不受影響，維持原值

順序與既有 tags/readingStatus 正規化一致：ID 正規化必須在 applyDefaults 之前，因 BookSchemaV2 的 `id` 為 required 但無 default，applyDefaults 不會補值。

附帶修復：`tests/test-setup.js` 新增 `crypto.randomUUID` polyfill（jsdom 26 的 crypto 物件缺少此方法，Chrome SW 環境原生支援，僅測試環境需補），供本 ticket 與後續任何呼叫 crypto.randomUUID() 的程式碼使用。
