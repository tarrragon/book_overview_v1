## Context Bundle

### 目標

修改 book-data-extractor.js 的 getPageType() 和 isExtractablePage() 委派給 platformAdapter，解決博客來和 Kobo 提取失敗。

### 根因

book-data-extractor.js:87-104 的 getPageType() 硬編碼只認 /library、/shelf、/book/ 路徑。博客來 URL (/viewer/index.html?readlist=all) 不含這些路徑，回傳 unknown，startExtractionFlow 第 176 行拒絕提取。

### 關鍵檔案

- src/content/extractors/book-data-extractor.js — 修改 getPageType() 和 isExtractablePage()
- src/content/content-modular.js:92 — 已有 bookDataExtractor.setPlatformAdapter(platformAdapter)

### 實作策略

1. 在 getPageType() 中：若 this.platformAdapter 存在，先 await this.platformAdapter.getPageType()，結果非 unknown 則直接回傳；否則 fallback 到既有硬編碼邏輯
2. 在 isExtractablePage() 中：若 this.platformAdapter 存在，先用 await this.platformAdapter.isExtractablePage()；否則 fallback 到既有邏輯
3. 注意 adapter 的 getPageType 是 async，extractor 的是 sync — 需確認呼叫端是否已在 async context
4. 既有 Readmoo 路徑不受影響（ReadmooAdapter.getPageType 也回傳 library）

### commit policy

- 分支: feat/1.6.0-W2-002-extractor-adapter-delegation
- commit 前綴: fix(1.6.0-W2-002)
