## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`event-coordinator.js:586` 使用 hardcoded `readmoo_books` 寫入 storage，所有書城的提取結果都覆蓋同一個 key。`data-processing-service.js:196` 同樣以 hardcoded `'readmoo_books'` 註冊處理器。

### 影響範圍

| 檔案 | 行號 | 問題 |
|------|------|------|
| `event-coordinator.js` | 558 | tags 陣列 hardcode `'readmoo'` |
| `event-coordinator.js` | 582 | source 預設 `'readmoo'` |
| `event-coordinator.js` | 586 | `chrome.storage.local.set({ readmoo_books: ... })` hardcoded key |
| `event-coordinator.js` | 588-589 | 驗證讀取 hardcoded `readmoo_books` |
| `data-processing-service.js` | 196 | 處理器註冊 hardcoded `'readmoo_books'` |

### 相關 Error Pattern

無直接相關 PC。父 ticket W2-003 Problem Analysis 已完整記錄 11 個影響檔案。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
event-coordinator.js：registerExtractionListeners handler 內新增 const source = event.data?.source || PLATFORM_IDS.READMOO，取代原本兩處各自的 hardcoded 'readmoo'（tags 陣列、storageData.source）。寫入與驗證讀取改用 platformBooksKey(source) 動態 key，取代 hardcoded 'readmoo_books'。

data-processing-service.js：initializeDataProcessors 內原本單一 hardcoded 'readmoo_books' 處理器註冊，改為 Object.values(PLATFORM_IDS).forEach 逐一以 platformBooksKey(platformId) 註冊，處理邏輯抽取為新方法 createBooksProcessor(platformId)（原邏輯不變，僅將處理本體內 source: 'readmoo' 改為 source = rawData.source || platformId 動態值）。

兩檔皆新增 import PLATFORM_IDS、platformBooksKey（from module-constants）。Readmoo 場景 source 預設值不變，向後相容 readmoo_books key。
