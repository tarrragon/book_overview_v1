## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

parseBookElement() (L229-237) 的 DOM 解析路徑完全無 bookId 欄位。API 路徑 _mapApiRecordToBookData() 已有 bookId: info.item，但 DOM fallback 沒有對應。

### 影響範圍

- src/content/adapters/books-com-tw-adapter.js L229-237 parseBookElement()
- tests/unit/adapters/books-com-tw-adapter.test.js L119-191 parseBookElement 測試群組

### Context Bundle

**bookId 提取策略分析**：

DOM 勘查結果（docs/bookstores/books-com-tw.md L146-162）顯示 .bookshelf__book 元素無 data-id attribute。可用 ID 來源：

1. **封面 URL path segment**（推薦）：`https://s3public-ebook.books.com.tw/cover/G000034891.jpg` 中 G000034891 與 API item 欄位一致。提取方式：coverUrl 檔名去副檔名。
2. **.book__cover a[href]**：勘查文件記錄 `a > img` 結構，但未記錄 href 內容，實機不確定有無 item query param。
3. **書名 hash**：用 title 做 deterministic hash 作 fallback，但跨書城可能碰撞。

**採方案 1 + fallback**：
- 優先從 coverUrl 提取檔名（去副檔名）作為 bookId
- coverUrl 為空或無法提取時，回傳空字串（與 API 路徑一致的 graceful degradation）
- 新增 _extractBookIdFromCoverUrl(coverUrl) 私有方法

**修改點**：
1. 新增 _extractBookIdFromCoverUrl(coverUrl) 私有方法
2. parseBookElement() 加入 bookId: this._extractBookIdFromCoverUrl(coverUrl) 欄位
3. 測試 mock 元素的封面 URL 已含 G000034891，驗證 parseBookElement 回傳含 truthy bookId

**commit policy**：feat branch 上單一 commit

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

依 Context Bundle 方案 1 實作：

1. 新增 `_extractBookIdFromCoverUrl(coverUrl)` 私有方法（`src/content/adapters/books-com-tw-adapter.js`）：以 `/` 分割取最後一段檔名、去除 query/hash、去除副檔名；coverUrl 為空或非字串時回傳空字串。
2. `parseBookElement()` 先呼叫 `_extractCoverUrl(element)` 取得 coverUrl，再以此推導 `bookId: this._extractBookIdFromCoverUrl(coverUrl)`，並將 coverUrl 沿用於回傳物件（避免重複查詢 DOM）。
3. 新增兩筆測試（`tests/unit/adapters/books-com-tw-adapter.test.js`）：正常路徑驗證 `bookId` 為 `G000034891`；元素缺少封面時驗證 `bookId` 回傳空字串（graceful degradation，與 API 路徑行為一致）。
