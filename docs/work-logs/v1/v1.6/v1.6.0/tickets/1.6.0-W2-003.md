## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

單一 storage key `readmoo_books`（定義於 `src/background/constants/module-constants.js:521`）承載所有書目資料。多書城場景下，後提取的書城會覆蓋前一個書城的資料。

### 影響範圍

以下檔案直接使用 `readmoo_books` key 或 `STORAGE_KEYS.READMOO_BOOKS`：

| 檔案 | 用途 | 行號 |
|------|------|------|
| `module-constants.js` | 常數定義 SSOT | 521 |
| `event-coordinator.js` | 提取後寫入 storage | 586-589 |
| `popup-message-handler.js` | 讀取書目 / 清除資料 | 385-389, 750-751, 812-813 |
| `popup.js` | 監聽 storage 變更 | 1100 |
| `sync-panel.js` | 讀取書庫 books 陣列 | 101-102 |
| `tag-storage-adapter.js` | 讀寫書目（tag 系統） | 260, 270, 272 |
| `export-service.js` | 匯出檔名前綴 | 186 |
| `data-processing-service.js` | 資料處理器註冊 | 196 |
| `install-handler.js` | 初始化 | 322 |
| `cover-to-reader.js` | 遷移腳本 | 224 |
| `chrome-storage-adapter.js` | keyPrefix 預設 `readmoo_` | 899 |

### 修復策略

1. `STORAGE_KEYS` 新增 helper function `platformBooksKey(platformId)` → `{platformId}_books`
2. 保留 `READMOO_BOOKS` 常數（向後相容 + 遷移基線）
3. 所有寫入點改用 `platformBooksKey(platform)` 動態 key
4. Overview 讀取點改為讀取所有 `*_books` key 後合併
5. 匯出加入 `source` 欄位標識來源書城

### Context Bundle

- 常數定義 SSOT: `src/background/constants/module-constants.js`
- 書城識別符來源: 多書城適配器（`src/content/` 或 `src/background/domains/extraction/`）
- 設計文件: `docs/data-flow-architecture.md`
