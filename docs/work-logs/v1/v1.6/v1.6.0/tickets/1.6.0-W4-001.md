## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

book-data-extractor.js 的 getPageType() 有 delegation chain：
1. 先嘗試 platformAdapter.getPageType()
2. adapter 無此方法或回傳 'unknown' 時，fallback 到 Readmoo 硬編碼 URL pattern

readmoo-adapter（factory 模式）不實作 getPageType / isExtractablePage / isValidDomain，靠 extractor fallback 運作。
books-com-tw-adapter 和 kobo-adapter（class 模式，繼承 PlatformAdapterInterface）完整實作這些方法。

這導致：
- Readmoo 的 getPageType 判斷實際由 extractor 硬編碼 fallback 執行（/library、/shelf 模式）
- 非 Readmoo 書城的 URL pattern 不符合 fallback 邏輯時會誤判
- 單元測試 mock 遮蔽了這條 fallback 路徑，runtime 才暴露

### 影響範圍

- src/content/platform/platform-registry.js — 書城偵測入口
- src/content/extractors/book-data-extractor.js — 頁面類型判斷 delegation chain
- src/content/adapters/readmoo-adapter.js — 缺 getPageType/isExtractablePage
- src/content/adapters/books-com-tw-adapter.js — 完整實作
- src/content/adapters/kobo-adapter.js — 完整實作

### 相關 Error Pattern

無既有 error-pattern（本 ticket 為預防性測試建立）

### Context Bundle

**測試目標**：建立整合測試驗證 PlatformRegistry.detect(url) → adapter 方法鏈路一致性

**鏈路層級**：
1. PlatformRegistry.detect(url) → { config, createAdapter }
2. createAdapter(options) → adapter instance
3. adapter.getPageType(url) → 'library' / 'unknown'
4. adapter.isExtractablePage(url) → true / false
5. 不匹配 URL → detect 回傳 null

**三書城 URL patterns**：
- Readmoo: https://read.readmoo.com/#/library（adapter 無 getPageType，測 extractor delegation）
- 博客來: https://viewer-ebook.books.com.tw/viewer/index.html?readlist=all（adapter 有 getPageType，靠 ?readlist 判斷）
- Kobo: https://www.kobo.com/tw/zh/library/books（adapter 有 getPageType，靠 /library/books 路徑判斷）

**Jest 模組解析**：`src/` 前綴透過 moduleNameMapper 對應 `<rootDir>/src/$1`

**測試檔案位置**：tests/integration/platform/multi-bookstore-url-to-extract.test.js

**關鍵發現**：readmoo-adapter 不繼承 PlatformAdapterInterface，是 factory 函式回傳物件；getPageType/isExtractablePage/isValidDomain 皆未實作。此缺口需額外 ticket 修復，本 ticket 先建立測試覆蓋暴露缺口。

**Commit Policy**：建立 feat branch `feat/1.6.0-W4-001-multi-bookstore-integration-test`，測試全綠後 commit

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
建立 `tests/integration/platform/multi-bookstore-url-to-extract.test.js`，以真實模組（非 mock）串接驗證 PlatformRegistry.detect -> adapter.getPageType -> isExtractablePage 全鏈路，覆蓋 Readmoo / 博客來 / Kobo 三書城。

**測試設計**：
- Readmoo：驗證 adapter 缺少 getPageType/isExtractablePage/isValidDomain（缺口斷言），並驗證 extractor 的 fallback delegation chain（`getLocation().href` 硬編碼判斷）在 library URL（`#/library`）回傳 'library'/true，不匹配 URL（`#/notifications`）回傳 'unknown'/false。
- 博客來 / Kobo：adapter 完整實作 getPageType(url)，直接以 URL 參數驗證 `?readlist=all` / `/library/books` 路徑判斷；並用 `extractor.setPlatformAdapter(adapter)` 驗證 extractor 正確委派給 adapter（非 fallback）。
- extractAllBooks 依 Context Bundle 指示僅驗證方法存在（`typeof adapter.extractAllBooks === 'function'`），不實際呼叫（需要真實 DOM 且非本 ticket 範圍）。
- 額外補「不匹配書城 URL」case：未註冊 hostname 與無效 URL 字串皆驗證 PlatformRegistry.detect 回傳 null。

**window.location 控制**：testEnvironment=jsdom，採 `Object.defineProperty(window, 'location', {writable:true, configurable:true, value:{...}})` 模式（沿用 tests/unit/content/utils/page-detection-utils-simple.test.js 既有慣例），因 extractor.getLocation() 與 adapter._currentUrl() 皆讀 `globalThis.location`/`window.location`。

**缺口驗證結果**：readmoo-adapter 確認不繼承 PlatformAdapterInterface、無 getPageType/isExtractablePage/isValidDomain 三方法；此缺口已由測試明確斷言鎖定行為（adapter 缺方法 -> extractor fallback 接手），修復本身不在本 ticket 範圍。
