## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

readmoo-adapter 是 factory 函式（createReadmooAdapter），回傳物件不繼承 PlatformAdapterInterface。
books-com-tw-adapter 和 kobo-adapter 是 class 模式，繼承 PlatformAdapterInterface 並實作 17 個抽象方法。
readmoo-adapter 缺少 getPageType / isExtractablePage / isValidDomain 三個頁面偵測方法。

book-data-extractor 的 getPageType() delegation chain:
1. 嘗試 platformAdapter.getPageType()
2. adapter 無此方法或回傳 'unknown' → fallback 到硬編碼 URL pattern（/library、/shelf、/reader）
Readmoo 靠 step 2 fallback 運作，但此 fallback 是 Readmoo 專屬邏輯，不適用其他書城。

### 影響範圍

- src/content/adapters/readmoo-adapter.js:194 — adapter 物件需補三方法
- tests/integration/platform/multi-bookstore-url-to-extract.test.js:48-87 — 需更新四個 Readmoo 測試（缺口斷言→行為驗證）

### Context Bundle

**實作方向**：在 adapter 物件（readmoo-adapter.js:194）補三方法：

1. getPageType(url)：
   - 接受可選 url 參數，無則用 getLocation().href
   - Readmoo 書庫 URL 特徵：hash 含 `#/library`（SPA hash routing）
   - reader URL 特徵：pathname 含 `/api/reader/`
   - 回傳 'library' / 'reader' / 'unknown'

2. isExtractablePage(url)：委派 getPageType(url) === 'library'

3. isValidDomain(url)：hostname 邊界比對 'readmoo.com'

**參考實作**：books-com-tw-adapter.js:152-186（同模式，差異在 URL 特徵判斷）

**測試更新**：
- tests/integration/platform/multi-bookstore-url-to-extract.test.js
  - 第 48 行 test：從「缺少方法」改為「方法存在且行為正確」
  - 第 52-54 行：`.not.toBe('function')` → `.toBe('function')` 並驗證回傳值
  - 第 58 行 test：從「extractor fallback」改為「adapter delegation」（驗證 adapter.getPageType 被呼叫而非 fallback）
  - 第 74 行 test：同上

**Readmoo URL 特徵**（SPA hash routing）：
- 書庫頁：`https://read.readmoo.com/#/library`（hash = #/library）
- 閱讀器：`https://read.readmoo.com/api/reader/{BOOK_ID}`（pathname 含 /api/reader/）
- 有效域名：readmoo.com（registry hostnames: read.readmoo.com, member.readmoo.com, readmoo.com）

**Commit Policy**：在當前 `feat/1.6.0-W4-001-multi-bookstore-integration-test` 分支繼續。commit msg 格式：`feat(1.6.0-W4-009): readmoo-adapter 補實作 getPageType/isExtractablePage/isValidDomain`

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
readmoo-adapter.js（factory 物件，位於「頁面偵測方法（PlatformAdapterInterface）」新增區塊，緊接於「標準介面」之前）新增三方法，模式對齊 books-com-tw-adapter.js:152-186：

- `isValidDomain(url)`：hostname 完全比對或子網域後綴比對 `readmoo.com`（VALID_HOSTNAME 常數，模組頂層新增）。解析失敗（空字串/無效 URL）設計性靜默回傳 false。
- `getPageType(url)`：接受可選 url，無則用 `getLocation().href`。`new URL(target).hash` 含 `#/library` -> 'library'；`pathname` 含 `/api/reader/` -> 'reader'；否則 'unknown'。解析失敗設計性靜默回傳 'unknown'。
- `isExtractablePage(url)`：委派 `getPageType(url) === 'library'`。

book-data-extractor 的 getPageType() delegation chain（優先呼叫 platformAdapter.getPageType()，'unknown' 才 fallback 硬編碼 URL pattern）現在對 Readmoo 也會在 adapter 層命中，硬編碼 fallback 路徑不再被觸發。

**附帶修復（regression fix，非 scope creep）**：實作後跑 npm test 發現兩個既有測試檔案因使用「不符真實 Readmoo SPA hash routing」的舊 fixture（https://readmoo.com/library，純 pathname、無 hash）而回歸失敗——這些測試先前能通過純粹是因為 adapter 缺方法、走 extractor 硬編碼 fallback（pathname.includes('/library')）掩蓋了問題。現在 adapter 優先介入，回傳 'unknown'（fixture 的 URL 沒有 #/library）。依 docs/bookstores/readmoo.md 記載真實書庫頁必為 https://read.readmoo.com/#/library（hash-based SPA routing），修正兩檔案 fixture 改用正確 hash URL：
- tests/unit/content/modular/content-modular.test.js：2 處 test-local globalThis.location（checkPageReady、startExtractionFlow 測試）改用 hash URL；startExtractionFlow 測試額外補 createReadmooAdapter({ document }) 缺漏的 document 注入（原本靠 globalThis.document fallback 找不到 DOM 元素，導致 waitForBookElements 空等滿 5000ms timeout 才 resolve，效能與穩定性皆有風險，現已修正為立即 resolve）。
- tests/integration/chrome-extension/content-script-extractor.test.js：JSDOM 建立時的 url 選項 + loadContentScript() helper 內的 globalThis.location override 皆改用 hash URL，影響全檔案共 4 個測試（原本因缺 hash 全部拋出「不支援的頁面類型: library」錯誤）。
