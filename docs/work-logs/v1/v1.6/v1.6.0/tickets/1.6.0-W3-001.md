## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

KoboAdapter 的 `extractAllBooks()` 目前僅解析當前頁面 DOM。Kobo 書庫是 SSR 多頁應用，超過 60 本書需透過 URL 參數 `pageNumber` 翻頁。Content script 無法自行 navigate（會失去執行 context），需透過 background service worker 代理 fetch 後續頁面 HTML。

### 影響範圍

| 檔案 | 變更類型 |
|------|---------|
| `src/content/adapters/kobo-adapter.js` | 修改 `extractAllBooks()` 加入分頁迴圈 |
| `src/background/messaging/content-message-handler.js` | 新增 `FETCH_PAGE_HTML` message type |
| `src/core/constants/` 或既有 message constants | 新增 message type 常數 |
| `tests/` | 新增/修改對應測試 |

### 架構策略

**SSR 分頁 fetch 路徑**：

```
Content Script (KoboAdapter)
  ├─ 解析當前頁面 (page 1)
  ├─ chrome.runtime.sendMessage({ type: 'FETCH_PAGE_HTML', url: page2Url })
  │   └─ Background SW: fetch(url) → response.text() → sendResponse({ html })
  ├─ DOMParser 解析回傳 HTML
  ├─ 重複直到最後一頁
  └─ 彙整所有書籍
```

**停止條件**：DOM 中 `li.item-wrapper.book` 數量 < 60（最後一頁），或 `.page-navigation` 不存在

**分頁參數**：`pageSize=60`（最大值）+ `pageNumber=N`（從 1 開始）

### 相關 Error Pattern

無直接相關。需注意 Chrome Extension 的 CORS 限制：background SW fetch 同域（kobo.com）頁面需 manifest `host_permissions` 配合。

### Context Bundle

**規格文件**：`docs/bookstores/kobo.md`（DOM 結構、分頁機制、選擇器速查）
**既有 adapter**：`src/content/adapters/kobo-adapter.js`（W2 成果，單頁解析已完成）
**介面契約**：`src/content/platform/platform-adapter-interface.js`（17 個抽象方法）
**參考模式**：`src/content/adapters/books-com-tw-adapter.js`（API 分頁 + DOM fallback 雙路徑）

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### Phase 1 功能規格

### 1. Background Fetch Message Protocol（新增跨 context 通訊能力）

**新 message type**: `CONTENT.FETCH.PAGE_HTML`

| 項目 | 值 |
|------|---|
| 方向 | Content Script → Background SW |
| 用途 | Content script 請求 background 代理 fetch SSR 頁面 HTML |
| 安全性 | Background handler 驗證 URL hostname 屬已註冊平台 |

**Request**:
```js
chrome.runtime.sendMessage({
  type: 'CONTENT.FETCH.PAGE_HTML',
  url: 'https://www.kobo.com/tw/zh/library/books?pageSize=60&pageNumber=2',
  platform: 'kobo'
})
```

**Response**:
```js
{ success: true, html: '<html>...</html>', status: 200 }
// 或
{ success: false, error: 'Fetch failed: 403 Forbidden' }
```

**安全約束**:
- handler 驗證 `url` hostname 屬已註冊平台域名（防任意 URL fetch）
- 超時 30 秒
- 回應大小無硬上限（一頁 HTML 約 200-500KB）

### 2. KoboAdapter `extractAllBooks()` 分頁迴圈

**修改範圍**: `extractAllBooks()` 方法

**流程**:
```
1. 解析當前頁面 DOM（page 1，沿用既有邏輯）
2. 從篩選器 "(N)" 取得總筆數 → 計算總頁數 ceil(total / 60)
3. for pageNumber = 2 to totalPages:
   a. 建構 URL: baseUrl + ?pageSize=60&pageNumber=N
   b. chrome.runtime.sendMessage({ type: 'CONTENT.FETCH.PAGE_HTML', ... })
   c. DOMParser 解析回傳 HTML
   d. querySelectorAll('li.item-wrapper.book') 取書目元素
   e. 逐一 parseBookElement → sanitizeData
   f. 追加至結果陣列
4. 回傳全部書籍
```

**停止條件**（防禦性，任一成立即停止）:
- pageNumber > 計算的 totalPages
- 該頁書目元素數量 = 0
- background fetch 失敗
- 累計頁數 > 100（硬上限防無限迴圈）

**新增私有方法**:
| 方法 | 職責 |
|------|------|
| `_extractTotalCount()` | 從 `.filter-chip` 的 `(N)` 文字解析總筆數 |
| `_buildPageUrl(pageNumber)` | 建構分頁 URL |
| `_fetchPageHtml(url)` | 透過 chrome.runtime.sendMessage 取得 HTML |
| `_parseHtmlToBooks(html)` | DOMParser 解析 HTML 並提取書目 |

**新增常數**:
```js
const PAGE_SIZE = 60
const MAX_PAGES = 100
const FETCH_TIMEOUT_MS = 30000
const TOTAL_COUNT_PATTERN = /\((\d+)\)/
```

### 3. manifest.json 確認

`host_permissions` 需包含 `*://*.kobo.com/*`（W2 已處理，確認即可）。

### 4. 驗收條件對齊

| AC | 實作位置 | 說明 |
|----|---------|------|
| 1. extractAllBooks | kobo-adapter.js | 修改為分頁迴圈 |
| 2. SSR 分頁 pageSize=60 | kobo-adapter.js | _buildPageUrl + 迴圈 |
| 3. DOM 解析正確 | kobo-adapter.js | 既有 parseBookElement 沿用 |

### 5. 拆分建議

Phase 1 分析後建議拆分為 2 個子 ticket：
- **W3-001.1**: Background fetch handler（新增 CONTENT.FETCH.PAGE_HTML 處理）
- **W3-001.2**: KoboAdapter 分頁迴圈（依賴 .1 的 handler，blockedBy .1）

**理由**：兩個功能職責可獨立測試、獨立驗收，且 .1 是跨書城通用能力（未來 BookWalker/Kindle 等 SSR 書城可重用）。
