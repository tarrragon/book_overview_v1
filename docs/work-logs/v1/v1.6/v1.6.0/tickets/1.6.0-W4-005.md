## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

歷史資料可能殘留無 ID 書目（stable-id-generator 實裝前 / 匯入資料缺 ID）。
v1-to-v2 遷移 L201 對無 ID 書目只跳過不修復（`if (!book.id) continue`）。
W4-002 已在 event-coordinator 正規化層解決「新提取書目」的 ID 問題，但既有 storage 資料需額外遷移腳本修復。

### 實作策略

新增遷移腳本 `src/data-management/migration/fix-missing-book-ids.js`：

1. 遍歷 storage 中所有 `*_books` key（用 PLATFORM_IDS 列舉）
2. 對每個 platform 的 books 陣列，找出 `id` 為 falsy 的書目
3. 為每本無 ID 書目生成 UUID（`crypto.randomUUID()`）
4. 若書目有 `bookId` truthy，同時映射為 `platformBookId`（對齊 W4-002 正規化邏輯）
5. 已有 truthy `id` 的書目不修改
6. 寫回 storage

### 遷移註冊

在 `SchemaMigrationService` 中註冊為可呼叫的遷移步驟，或作為獨立修復函式供手動/自動觸發。參考 v1-to-v2.js 的備份→轉換→寫回模式。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 `src/data-management/migration/fix-missing-book-ids.js`：

- `fixMissingBookIds(storage, logger)`：主流程，遍歷 `PLATFORM_IDS` 對應的所有 `platformBooksKey`（readmoo_books / books_com_tw_books / kobo_books / bookwalker_books / kindle_books），偵測是否有 falsy id 書目；無則 `{ fixed: false, reason: 'no_missing_ids' }` 跳過。
- 有缺失時先 `createBackup` 寫入 `migration_backup_missing_ids`（含所有受影響 platform key 原始 snapshot），失敗則中止。
- `fixBooksMissingIds` / `fixBookId`：對每本缺失 id 書目，若 `bookId` truthy 先映射為 `platformBookId`（對齊 W4-002 event-coordinator 正規化邏輯），再以 `globalThis.crypto.randomUUID()` 補生成 id；已有 truthy id 的書目原樣保留（同引用不修改）。
- 寫回成功後移除 backup key；寫回過程拋錯則呼叫 `rollbackMigration` 從 backup 還原所有受影響 key。
- 拆分 `collectSnapshot` / `applyFixes` 輔助函式，維持 `fixMissingBookIds` 主函式在認知負擔閾值內（<=30 行）。

未修改 `SchemaMigrationService`（獨立修復腳本，依 ticket 範圍不掛入既有遷移註冊流程）。
