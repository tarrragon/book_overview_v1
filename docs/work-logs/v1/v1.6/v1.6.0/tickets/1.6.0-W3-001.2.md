### Context Bundle (Phase 3b)

**分支**：`feat/1.6.0-W3-001-kobo-ssr-pagination`（沿用）

**前置依賴**：W3-001.1 已完成（commit 08666b8dc），`CONTENT.FETCH.PAGE_HTML` handler 可用

**RED 測試**：`tests/unit/adapters/kobo-adapter-pagination.test.js`（16 案例，13 RED）

**修改目標**：`src/content/adapters/kobo-adapter.js`

**需新增的私有方法**：

1. `_extractTotalCount()` — 從 DOM `.filter-chip` 取 `(N)` 解析總筆數，找不到回傳 0
2. `_buildPageUrl(pageNumber)` — 回傳 `https://www.kobo.com/tw/zh/library/books?pageSize=60&pageNumber=N`
3. `_fetchPageHtml(url)` — `chrome.runtime.sendMessage({ type: 'CONTENT.FETCH.PAGE_HTML', url })`，success 回傳 html，fail 拋 Error
4. `_parseHtmlToBooks(html)` — `new DOMParser().parseFromString(html, 'text/html')` → `querySelectorAll('li.item-wrapper.book')` → 逐一 `parseBookElement` + `sanitizeData` → 回傳陣列

**修改既有方法**：

`extractAllBooks()` 加入分頁迴圈：
- 解析當前頁面（既有邏輯保留）
- `_extractTotalCount()` 取總筆數，算 `totalPages = ceil(total / PAGE_SIZE)`
- 若 totalPages <= 1 → 不分頁，直接回傳
- 否則 for pageNumber 2..totalPages → `_fetchPageHtml(_buildPageUrl(n))` → `_parseHtmlToBooks(html)` → 追加
- 4 個停止條件：超過 totalPages / 該頁 0 本 / fetch 失敗 / 硬上限 MAX_PAGES=100

**新增常數**：
```
const PAGE_SIZE = 60
const MAX_PAGES = 100
const TOTAL_COUNT_PATTERN = /\((\d+)\)/
const FILTER_CHIP_SELECTOR = '.filter-chip'
```

**commit policy**：測試全綠後 commit，message 含 ticket ID
