## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

Overview/Popup 讀取端全部 hardcode `readmoo_books`，只能顯示 Readmoo 書目。

### 影響範圍

| 檔案 | 行號 | 問題 |
|------|------|------|
| `popup-message-handler.js` | 385-389 | 讀取書目 hardcode `readmoo_books` |
| `popup-message-handler.js` | 750-751 | 匯出前檢查 hardcode `readmoo_books` |
| `popup-message-handler.js` | 812-813 | 清除資料 hardcode `readmoo_books` |
| `popup.js` | 1100, 1102 | storage.onChanged 只監聽 `readmoo_books` |
| `sync-panel.js` | 101-102 | 讀取書庫 hardcode `STORAGE_KEYS.READMOO_BOOKS` |

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 既有基礎設施復用

`loadAllPlatformBooks()` 已存在於 `src/storage/helpers/multi-platform-storage.js`（W2-003.1 建立），
遍歷 `PLATFORM_IDS` 產生所有 `*_books` key，一次 `chrome.storage.local.get()` 後合併非空書城的 `books`
陣列。本 ticket 直接復用，未重複實作。

### 5 處修改點

1. **`popup-message-handler.js:385-391`**（`handlePopupDataRequest` 'books' case）：改用
   `loadAllPlatformBooks()`；`count` 改為合併陣列長度，`lastExtraction` 因合併後無單一時間戳語意改回傳 `null`
   （原欄位無下游消費者引用，經 grep 確認安全）。
2. **`popup-message-handler.js:749-751`**（`requiresData` 權限檢查）：改用 `loadAllPlatformBooks()`
   檢查是否任一書城有資料。
3. **`popup-message-handler.js:811-815`**（`handleStorageClear` 'books' case）：改用
   `Object.values(PLATFORM_IDS).map(platformBooksKey)` 產生全平台 key 陣列後一次 `remove()`。
4. **`popup.js:1098-1103`**（`setupExtractionCompletionListener`）：`changes.readmoo_books` 固定比對
   改為 `Object.keys(changes).find(key => key.endsWith('_books'))` 動態匹配任一書城 key；同步更新函式頭部
   業務情境註解。
5. **`sync-panel.js:_loadBooks`**：移除 `STORAGE_KEYS.READMOO_BOOKS` 單一讀取，改用 `loadAllPlatformBooks()`；
   同步移除已無用的 `STORAGE_KEYS` import，改 import `loadAllPlatformBooks`（ESM `import` 對 CJS
   `module.exports` 具名解構，與既有 `STORAGE_KEYS` import 手法一致，esbuild bundle 已驗證可行）。

### 測試調整

- `sync-panel.test.js`「重複點擊同步時 isProcessing 防止並行流程」：`_loadBooks` 多一層
  `loadAllPlatformBooks()` async 呼叫，microtask 鏈由 2 層變 3 層，原本 2 次 `await Promise.resolve()`
  改為 3 次以正確等待 storage 讀取完成後才呼叫 encoder（非計時斷言，屬 microtask 排序等待，符合
  test-assertion-design-rules）。
- `popup-storage-completion-listener.test.js`：新增「非 readmoo 書城（kobo_books）變更亦應觸發成功訊息」
  場景，驗證 acceptance 2（storage 變更監聽匹配所有 `*_books` key）。
