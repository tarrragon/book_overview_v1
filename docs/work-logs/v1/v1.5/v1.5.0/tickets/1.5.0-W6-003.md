實測確認 APP 端 `book_overview_app/docs/spec/design-system-spec.md` §14.6「跨平台元件對照表」已產出（contract-version: v1，spec 變更歷史 1.1 記載 2026-07-09 寫入）。外部依賴**已解除**，本 ticket 僅剩 blockedBy W6-002。

契約要點（執行時依此對齊）：
- 按鈕 variant 映射：AppButton.action=primary / .confirm=confirm（v1 待補）/ .caution=danger / .neutral=secondary / .ghost=ghost（v1 待補）
- 命名規則：v1 既有 primary/secondary/danger 保留為別名，新增契約以語意名為準
- size 對齊：雙端共用 small/medium/large（v1 現況 normal/small 需對齊）
- token 引用：雙端引用同名 token；注意 V1 用 success/warning 主名、APP 用 positive/negative 主名（APP 有 success/warning 別名，需在執行時確認對齊方式）
### WRAP 三問（認領 Checkpoint）

- **W（其他做法）**：(a) 直接重命名既有 variant 對齊契約——棄，違反契約規則「v1 既有 primary/secondary/danger 保留為別名」且破壞 4 個 popup 引用點；(b) 新增契約語意名 + 既有名保留——採，契約明文規定。
- **A（機會成本）**：本票是 W6-005（測試同步）的邏輯前置，先做可減少 W6-005 重工；不擠壓其他 W6 票。
- **P（最可能失敗）**：token 主名差異（V1 success/warning vs APP positive/negative）處理過頭——誤把 token 重命名納入本票。防護：token 值層/主名統一屬 W6-006（PROP-014 評估）與 W6-007（token manifest）範圍，本票僅比對元件引用並記錄差異，禁止重命名 design-system token 主名。

### Scope 邊界（PM 派發前劃定）

- **In**：createButton variant 補 `confirm`/`ghost`（契約標 v1 待補）、size 對齊 small/medium/large（既有 normal/small 保留相容，normal 映射 medium）、既有元件（button/card）語意名與 token 引用逐項比對契約表並修正/記錄差異、受影響既有測試修正保持 npm test 100%。
- **Out**：divider 元件（W6-004）、新元件測試補充（W6-005）、card raised/inset/engraved 與 dialog/badge/input 新建（契約標 v1 待建）、token 主名重命名（W6-006/W6-007）。若判定待建元件 1.5.0 內缺票，用 add-spawn-request 上報，不自行擴 scope。
