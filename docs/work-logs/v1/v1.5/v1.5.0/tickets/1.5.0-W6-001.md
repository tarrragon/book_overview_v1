#### 2. Generator 修改策略（關鍵設計決策）

**資料組織方式：獨立來源模組 `src/core/design-system/component-rules.js`，單一 template literal 常數（採用），非 generator 內聯字串**。理由：(a) generator 現僅 147 行、職責為 token 映射邏輯，內聯約 240 行 CSS 字串會使檔案體量近三倍且混合「映射邏輯」與「規則內容」兩職責；(b) 與既有 SSOT 模式一致——generator 一律 require 來源模組（colors/spacing/typography/shadows），component-rules 成為第 5 個來源模組；(c) validate:design-system 的 git diff 防漂移鏈自然涵蓋新模組。不採結構化物件（如 {selector, declarations} 陣列）：規則是逐字搬運的既有 CSS，結構化需寫序列化器，屬過度設計（ARCH-010：不引入新抽象）。
