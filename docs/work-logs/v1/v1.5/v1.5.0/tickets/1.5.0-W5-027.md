## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 根因補充

Context Bundle 記載的根因（checkCurrentTab() 只在 initialize() 呼叫一次）與現行程式碼有落差：
periodicStatusUpdate（0.19.0-W1-062.1 引入）已用 setInterval(3000ms) 週期呼叫 checkCurrentTab()，
非終態時本就會重試。本次仍依 Context Bundle 策略新增獨立輪詢機制，理由：
(1) 3 秒週期對「剛開 popup 等 content script 注入」的場景仍嫌慢；
(2) 新增機制與既有週期更新解耦，任一方失效不影響另一方；
(3) ticket acceptance 明確要求「新增自動更新機制」而非依賴既有副作用。

### 實作內容

- `src/popup/constants/layout.js`：新增 `CONTENT_SCRIPT_POLL_CONFIG`
  （`INTERVAL_MS: 1500`, `MAX_RETRIES: 10`）
- `src/popup/popup.js`：
  - 新增模組級狀態 `contentScriptPollTimerId` / `contentScriptPollAttempts`
  - 新增 `stopContentScriptPolling()` / `pollContentScriptOnce(tab)` / `startContentScriptPolling(tab)`
  - `checkCurrentTab()` PING 失敗（catch）時呼叫 `startContentScriptPolling(tab)`；
    PING 成功、非書庫頁面分支呼叫 `stopContentScriptPolling()` 防止殘留計時器
  - popup `unload` 事件呼叫 `stopContentScriptPolling()` 清理
  - 暴露 `window.stopContentScriptPolling` / `getContentScriptPollAttempts` /
    `isContentScriptPolling` / `CONTENT_SCRIPT_POLL_CONFIG` 供測試使用
- 新增測試 `tests/unit/popup/popup-content-script-poll.test.js`（6 案例，
  涵蓋常數驗證、輪詢啟動、狀態轉換「載入中→就緒」、最大重試停止、
  重複呼叫防重複計時器、popup 關閉清理）

## Context Bundle

### 目標

popup 開啟後若 content script 尚未就緒，自動輪詢重試直到連線成功或超時，無需用戶手動關閉再開。

### 關鍵檔案

- src/popup/popup.js — checkCurrentTab() 函式（~934 行）
- src/popup/constants/layout.js — 時序常數
- tests/unit/popup/ — 測試目錄

### 根因

checkCurrentTab() 只在 popup 初始化（initialize()）時呼叫一次。content script 注入時機可能晚於 popup 開啟，導致 PING 失敗後 UI 停留在「正在連線」不再更新。

### 實作策略

方案：setInterval 輪詢（不修改 content script，簡單穩健）

1. checkCurrentTab() PING 失敗時啟動 setInterval（間隔 1500ms）
2. 每次輪詢重新 sendMessage PING
3. 成功時 clearInterval + 更新 UI 為「就緒」
4. 設最大重試次數（10 次 = 15 秒），超時停止輪詢
5. popup 關閉時自動停止（popup unload / beforeunload clearInterval）

### 常數建議

在 src/popup/constants/layout.js 新增：
- CONTENT_SCRIPT_POLL_INTERVAL_MS: 1500
- CONTENT_SCRIPT_POLL_MAX_RETRIES: 10
