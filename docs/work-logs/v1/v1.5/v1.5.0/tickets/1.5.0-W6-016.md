修復 ticket CLI append-log H2 自動降級誤改 code fence 內文字

## Problem Analysis
### 問題根因（PM 前台定位）

`commands/track_acceptance.py:729` 的 H2 自動降級（W1-068 方案 B）使用 `re.sub(r'(?m)^## ', '### ', content)` 對整段 content 無差別替換，未辨識三反引號 code fence 圍欄區間，導致 fence 內引用的 `## ` 字面（如 grep 輸出範例、markdown 教學片段）被誤降為 `### `，引用字面失真。

### 影響範圍

- `commands/track_acceptance.py` L716-729（`schema_sections_for_h2_check` 降級區塊）
- 觸發條件：`--section` 為 Schema 章節（Solution / Test Results / Problem Analysis / Context Bundle / NeedsContext / Exit Status / Completion Info）且 content 含行首 `## `
- 測試位置：`ticket_system/tests/`（pytest，`npm run test:hooks` 執行）

### WRAP 三問

- W（候選方案）：(a) 逐行掃描 + fence 狀態機（三反引號 toggle），fence 內不替換——採用；(b) 先抽出 fence 區塊替換後回填——複雜度較高且邊界易錯。
- A（機會成本）：P3 小修，不擠壓 W6 其他票；單檔單函式範圍。
- P（最可能失敗）：fence 邊界判定錯誤（如 ``` 帶語言標注、行內反引號誤判、未閉合 fence）。防護：pytest 覆蓋帶語言標注 fence、未閉合 fence、fence 外仍正常降級三類案例。

### 相關 Error Pattern

無直接對應 PC；性質同 W6-013 附帶發現記錄。

## Solution
### 修復方案：fence 狀態機（WRAP 方案 a）

新增 _downgrade_h2_outside_fence(content) helper（commands/track_acceptance.py），
逐行掃描 content，行首三反引號（含帶語言標注如 bash fence）toggle in_fence 狀態；
in_fence=False 且行首匹配 ^## 才降級為 ### ，fence 內文字原樣保留。
未閉合 fence 進入後直到結尾都視為 fence 內，保守不改寫。

原呼叫點（L716-729）改為呼叫 helper 取代 re.search/re.sub，
回傳值含 downgrade_happened 布林，僅實際發生降級時才輸出 stderr WARNING
（原本邏輯亦是 conditional，行為未變，僅判斷依據從「是否含 H2」改為
「fence 外是否有 H2」）。

未修改 SCHEMA_H2_SECTIONS 白名單、未移除自動降級機制本身，
符合 L714 修改注意事項（無需更新 context-bundle-spec.md）。
