## Problem Analysis
### 問題根因（PM 前台定位）

ticket 描述的假說（create 模板 vs CANONICAL_BODY_SECTIONS 漂移）經查證修正：SSOT `ticket_system/constants.py` L349-360 的 `CANONICAL_BODY_SECTIONS` **已含** "Spawn Requests"（10 章），模板（`lib/ticket_builder.py` L946）與 SSOT 一致。實際漂移在 `.claude/hooks/acceptance_checkers/` 的自維護副本 `_SCHEMA_SECTION_NAMES`（9 項，缺 "Spawn Requests"）：

| 檔案 | 清單狀態 |
|------|---------|
| `acceptance_checkers/custom_h2_checker.py` L23-33 | 9 項，缺 Spawn Requests → W17-072 誤報源頭 |
| `acceptance_checkers/execution_log_checker.py` L13-23 | 9 項，缺 Spawn Requests |
| `acceptance_checkers/ticket_validator.py` | 無 `_SCHEMA_SECTION_NAMES` 清單（註解提及的三處同步已剩兩處） |

custom_h2_checker 檔頭註解自承「三處將於 ARCH-020 refactor 收斂」——本票不做跨 package import 收斂（hooks 與 ticket_system 分屬不同執行環境），僅補值消除誤報；收斂屬 ARCH-020 既有追蹤範圍。

### WRAP 三問

- W（候選）：(a) 兩副本補 "Spawn Requests"（採用，最小修正）；(b) 跨 package import constants.py（ARCH-020 範圍，hooks UV single-file 環境 import 路徑複雜）；(c) 模板移除 Spawn Requests 章節（該章節是 W17-010 spawn request 協議正式載體 + add-spawn-request CLI 寫入目標，不可移）
- A（機會成本）：P3 小修，兩檔各 1 行 + 測試
- P（最可能失敗）：execution_log_checker 補值後語意副作用——該清單另用於 execution log 填寫判定，新增章節可能改變「已填寫」判準（防護：實作者先讀該清單全部使用點，pytest 覆蓋 + npm run test:hooks 全套件迴歸）

## Solution
`custom_h2_checker.py` 與 `execution_log_checker.py` 的 `_SCHEMA_SECTION_NAMES`（各 9 項）補 "Spawn Requests"，與 SSOT `ticket_system/constants.py` CANONICAL_BODY_SECTIONS（10 章，已含 Spawn Requests）對齊。兩處清單各補一行並加註解「與 ticket_system/constants.py CANONICAL_BODY_SECTIONS 同步（1.5.0-W6-018）」。TDD：先在 `test_custom_h2_checker.py` / `test_execution_log_checker.py` 新增測試（RED 確認 `find_custom_h2_sections` 對模板自生 `## Spawn Requests` 誤報），再補值（GREEN）。

### 自檢結果

execution_log_checker 副作用評估：`_SCHEMA_SECTION_NAMES` 除了 `find_custom_h2_sections` 誤報判準外，另用於 `_find_schema_section_boundary_regex()` 決定 Solution/Test Results/重現實驗結果 三個「已填寫」檢查的區段邊界。新增 "Spawn Requests" 只是把它從「非邊界（會被吞併進前一 schema 章節內容）」改為「有效邊界」。由於 `check_execution_log_filled` 僅檢查 Solution / Test Results / 重現實驗結果三個章節，模板中 Spawn Requests 章節本身不在檢查範圍內，且其固定佔位 HTML 註解內容原本即使被吞併也會被既有的 `<!-- ... -->` 剝除邏輯清空，故補值前後對「已填寫」判準無語意差異，僅修正邊界辨識更準確。已用 `test_spawn_requests_recognized_as_schema_boundary` 覆蓋此邊界情境（驗證 Test Results 內容不吞入 Spawn Requests 佔位符）。

ticket_validator.py 未含 `_SCHEMA_SECTION_NAMES` 清單（既有三處同步註解已剩兩處現況，非本票引入），不在本票修改範圍內。三處收斂屬 ARCH-020 既有追蹤範圍。
