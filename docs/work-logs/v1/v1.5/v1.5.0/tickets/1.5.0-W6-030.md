## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

W6-022 遷移 promptImportMode 到 createDialog 後，靜態 HTML 元素行為改變：

| 元素 | 遷移前 | 遷移後 |
|------|--------|--------|
| `#importModeOverlay` | 被設為 `display:block` 顯示 | 永久 `display:none`（存在性防禦錨點） |
| `#importModeOverwriteBtn` / `#importModeMergeBtn` | 接受 click 事件 | 無事件監聽（不互動） |
| createDialog 動態 overlay | 不存在 | `div.modal-overlay`（無 ID），`display:flex` 時可見 |
| createDialog 動態按鈕 | 不存在 | `button.button.primary`（無 ID），文字 = action.text |

E2E 測試仍用靜態 ID 選擇器（`#importModeOverlay` / `#importModeOverwriteBtn`），會永遠等待不到可見元素而 timeout。

### 影響範圍

| 檔案 | 受影響函式 | 受影響行 |
|------|-----------|---------|
| `tests/e2e/browser/uc04-import.e2e.test.js` | `importFixture()` | L208-214（步驟 4-5） |
| `tests/e2e/browser/uc07-error-handling.e2e.test.js` | `injectImport()` | L358-366（modal 等待+點擊） |

### 修復策略

改用動態查詢 createDialog 產出的 DOM：

1. **等待 overlay 出現**：`page.waitForFunction` 檢測 `.modal-overlay` 元素 `style.display === 'flex'`（createDialog open() 設定的 inline style）
2. **按文字找按鈕並點擊**：`page.evaluate` 在可見 overlay 內找 `button` 元素，以 `textContent` 匹配
   - `mode === 'overwrite'` → 文字 `'覆蓋（清空現有書庫）'`
   - `mode === 'merge'` → 文字 `'合併（保留現有書庫）'`
3. **等待 overlay 消失**：`page.waitForFunction` 確認無可見 `.modal-overlay`

### 相關 Error Pattern

無直接對應。本問題為 W6-022 遷移的預期後續工作（source_ticket spawn）。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
importFixture()（uc04）與 injectImport()（uc07）改用 createDialog 動態查詢取代靜態 ID 選擇器：

1. 等待 overlay 出現：page.waitForFunction() 檢測 document.querySelector('.modal-overlay') 存在且 overlay.style.display === 'flex'（對齊 ui-factory.js createDialog open() 的實作）。
2. 依按鈕文字找到並 click：page.evaluate() 在 overlay 內 querySelectorAll('.modal-actions button')，以 textContent 比對「覆蓋（清空現有書庫）」/「合併（保留現有書庫）」（對齊 import-flow-controller.js promptImportMode 的 actions 文案），找不到時拋 [SETUP] 前綴錯誤。
3. 等待 overlay 收斂：page.waitForFunction() 確認 .modal-overlay 不存在或 style.display === 'none'。

uc07 injectImport() 保留原有 try/catch 容錯（modal 未出現時視為 validate 階段已拋錯，不阻斷後續斷言）。
