### 全量分歧盤點結果（V1 4 檔 vs APP 對應檔，含 APP 單端獨有 3 檔）

比對對象：V1 src/core/design-system/{colors,shadows,spacing,typography}.js（4 檔，148 行）vs APP lib/core/design_system/{colors,shadows,spacing,typography,border_radius,animations,component_sizes}.dart（7 檔；buttons.dart 為組合式元件樣式模組，非扁平 token，排除逐項列舉，詳見 manifest sourceFiles.appExcluded）。

**盤點修正**：派發時 Context Bundle 標記 border_radius.dart 為「APP 單端獨有」，實測後發現與 V1 spacing.js 的 BORDER_RADIUS 常數高度對應（xs/sm/md/lg/xl 共 5 個共值，僅 circular 為 APP 獨有新增），非全檔單端獨有。manifest 依實測結果建立，此修正已寫入 domains.borderRadius.notes。

**三類分佈（全域 114 個可比對 token）**：

| 類別 | 數量 | 比例 |
|------|------|------|
| 共值 shared | 32 | 28.07% |
| 平台校準 calibrated | 17 | 14.91% |
| V1 獨有 platformOnlyV1 | 13 | 11.40% |
| APP 獨有 platformOnlyApp | 52 | 45.61% |

**matched-pair 校準比例（schema 設計關鍵輸入）**：
- 全域 matched-pair（shared+calibrated=49）：校準比例 34.69%
- colors 域單獨 matched-pair（20）：校準比例 **75.00%**（> 50%，即 linux 審查具體指涉的域——V1 全 palette 為有意平台校準，非漂移）

domains 明細：colors 38（5 shared/15 calibrated/6 v1Only/12 appOnly）、statusColors 6（全 v1Only，Readmoo 閱讀狀態 APP 無對應）、spacing 14（7 shared/7 appOnly）、borderRadius 6（5 shared/1 appOnly）、typography.fontFamily 1（shared）、fontSizes 13（9 shared/4 appOnly）、fontWeights 5（全 shared）、lineHeight 3（全 appOnly，V1 尚無行高 token）、shadowColors 2（全 calibrated：V1 中性黑 alpha vs APP primary 色相派生 alpha，角色對應但技術路線不同）、overlayColors 1（v1Only，APP 未定義 modal scrim token）、animations 7（appOnly）、componentSizes 18（appOnly，另 3 個需 BuildContext 的響應式函式排除於逐項列舉）。

**V1 缺口項顯性標記**：divider 系列（dividerSubtle/Normal/Strong，見 colors 域與說明）為 V1 明確缺口——APP 以陰影模擬分隔線已有完整語意 token，V1 分隔線仍直接寫在 CSS 未收斂至 design-system；manifest 內以 notes 欄位顯性標記「V1 缺口項」，未強行補值。

### Manifest JSON Schema 決策

依 colors 域校準比例 75% > 50% 觸發 acceptance 條件：schema 支援「無 base 值」列型態。設計如下：

- 每個 token 條目固定欄位：`key`（token 名）、`category`（shared/calibrated/platformOnlyV1/platformOnlyApp 四值 enum，於 categoryEnum 定義語意）、`base`（雙端共同基準值；category=shared 時填值，其餘三類固定為 `null`——即 acceptance 要求的無 base 值列型態）、`platforms.v1`/`platforms.app`（各自 `path` 定位原始常數路徑 + `value`；無對應時整個平台物件為 `null`）、`notes`（選填，記錄校準理由 / 缺口說明 / 結構差異，即 acceptance 要求的覆蓋理由欄位）。
- 頂層 `inventorySummary` 內建 `byCategory`（含百分比）+ `matchedPairAnalysis`（全域與 colors 域校準比例，供後續漂移偵測票 W6-008 直接讀取判斷閾值）+ `byDomain`（各域細分計數），落地「機器可讀」需求，avoiding 後續 W6-008 重算。
- `categoryEnum` 明文定義四類語意（含中文說明），供非本票撰寫者理解分類依據，不需回頭查 ticket。
- `sourceFiles.appExcluded` 記錄 buttons.dart 排除理由（組合式元件樣式模組非扁平 token，逐項列舉會與已收錄來源 token 重複計數）。

### 已知限制（供 W6-008 等後續票承接）

- shadowColors 域的「角色對應」（V1 sm/md 對應 APP shadowLight/shadowStrong）為人工語意判斷，非自動化演算法產出；後續若新增陰影 token 需人工維護對應關係。
- STATUS_COLORS（Readmoo 閱讀狀態，12 值）目前全數為 V1 獨有；若 APP 端未來新增閱讀狀態 UI，需回頭補 APP 對應 token 並更新 manifest。
