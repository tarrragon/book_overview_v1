## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

現行 `track_runqueue.py` 排序邏輯（L322-323, L420-422）為 `(_priority_rank(t), str(t.get("id", "")))`，僅依 priority → id 字串排序。缺少兩個維度：

1. **type 權重**：同 priority 的 ANA 與 IMP 排列無差異，PM 無法從 runqueue 輸出直覺判斷「先做分析再做實作」
2. **並行可行性**：runqueue 不標示哪些 ticket 可並行派發，PM 須人工逐一判斷 where.files 重疊性

### 影響範圍

- `.claude/skills/ticket/ticket_system/commands/track_runqueue.py` — list 和 DAG 兩處 sort key
- `.claude/pm-rules/decision-tree.md` — 若機制變更需同步路由描述
