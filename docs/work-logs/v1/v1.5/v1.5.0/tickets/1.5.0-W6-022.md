## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

v1 現有 3 個對話消費點各自實作，未走共用工廠：
1. **UC-04 Modal A**（import-flow-controller.js L128-222）：匯入模式選擇 modal（overwrite/merge/cancel），手刻 DOM + overlay + focus trap + Esc + 單實例保護
2. **UC-04 Modal B**（import-flow-controller.js）：空檔案覆蓋二次確認 modal（proceed/cancel），同樣手刻 DOM
3. **import-panel.js L145**：防舊蓋新確認以原生 `window.confirm()` 實作，同步阻塞且無法控制外觀

### 影響範圍

| 檔案 | 變更類型 |
|------|---------|
| src/core/ui/components/ui-factory.js | 新增 createDialog 工廠函式 |
| src/overview/import-flow-controller.js | Modal A/B DOM 建構改走 createDialog |
| src/popup/components/import-panel.js | window.confirm 升級為 createDialog confirm |
| src/overview/overview-page-controller.js | 可能需移除 modal 相關 elements 查找 |

### 設計約束

1. **契約對齊**：§14.6 定義 `createDialog({variant:'confirm'|'alert'})` 引用 `UIShadows.dialog` token，l10n key 為 `confirm`/`cancel`
2. **純 DOM 工廠模式**：ui-factory 現有函式皆為無狀態純函式回傳 HTMLElement；dialog 需生命週期管理（Promise 解析），必須擴展模式
3. **測試介面不變**：`promptImportMode()` 回傳 `Promise<'overwrite'|'merge'|null|symbol>` 介面 54 個 TC 不可破壞
4. **可達性**：role="dialog"、aria-modal="true"、焦點陷阱、Esc 關閉（既有行為不可退化）
5. **UIShadows.dialog token**：`SHADOW_COLORS.md`（0 8px 16px rgba(33,150,243,0.16)）+ `OVERLAY_COLORS.scrim`（rgba(0,0,0,0.5)）

### 相關 Error Pattern

無直接相關 PC。注意 PC-165（測試綠燈不等於 Runtime 正確）：遷移後需確認實際 DOM 行為非只靠測試。
