## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### Phase 1 功能規格：createDialog 工廠函式

### 1. API 設計

```javascript
/**
 * 建立對話框元素與生命週期控制器。
 *
 * 與其他 ui-factory 函式（回傳純 HTMLElement）不同，dialog 天生需要
 * 生命週期管理（show → user action → close → resolve），故回傳
 * { overlay, open() } 複合物件。此為 ui-factory 首個「元件+控制器」模式。
 *
 * @param {Object} options
 * @param {'confirm'|'alert'} options.variant - 必填
 * @param {string} [options.title] - 對話框標題
 * @param {string|HTMLElement} [options.message] - 訊息內容
 * @param {Array<{value: string, text: string, variant?: string}>} [options.actions]
 *   - 按鈕清單（confirm 預設 [{value:'confirm',text:'確認'},{value:'cancel',text:'取消'}]）
 *   - alert 預設 [{value:'dismiss',text:'確定'}]
 * @param {Object} [options.aria] - 無障礙屬性覆蓋
 * @param {string} [options.aria.labelledby] - aria-labelledby 目標 id
 * @param {string} [options.aria.describedby] - aria-describedby 目標 id
 * @returns {{ overlay: HTMLElement, open: () => Promise<string|null> }}
 *   - overlay: 完整 DOM 樹（遮罩+對話框+按鈕）
 *   - open(): 顯示對話框，回傳 Promise：
 *     - resolve(actionValue) 按鈕點擊
 *     - resolve(null) 取消（Esc / 遮罩點擊）
 */
function createDialog ({ variant, title, message, actions, aria } = {})
```

### 2. DOM 結構契約

```html
<div class="modal-overlay" style="display:none">         <!-- overlay -->
  <div class="modal-dialog" role="dialog" aria-modal="true"
       aria-labelledby="{titleId}" aria-describedby="{descId}">
    <h2 class="modal-title" id="{titleId}">{title}</h2>
    <p class="modal-description" id="{descId}">{message}</p>
    <div class="modal-actions">
      <!-- actions 逐一以 createButton 建立 -->
    </div>
  </div>
</div>
```

- class 名稱對齊既有 overview.css `.modal-overlay` / `.modal-dialog` 等已有樣式（不新增 CSS）
- box-shadow 由 CSS class 配合 design-system token 套用（`UIShadows.dialog`）
- `titleId` / `descId` 以 `crypto.randomUUID()` 或計數器自動產生（避免 ID 碰撞）

### 3. 行為規格

| 行為 | confirm variant | alert variant |
|------|----------------|---------------|
| 按鈕數 | >= 2（可自訂） | 1（dismiss） |
| Esc 鍵 | resolve(null) | resolve(null) |
| 遮罩點擊 | resolve(null)（target===overlay 才觸發，冒泡不觸發） | resolve(null) |
| 焦點陷阱 | Tab/Shift+Tab 在按鈕集合循環 | 同左 |
| 初始焦點 | 第一個 action 按鈕 | dismiss 按鈕 |
| 關閉後焦點還原 | open() 呼叫前的 document.activeElement | 同左 |
| 單實例保護 | 重複呼叫 open() 回傳同一 pending Promise | 同左 |
| open() 生命週期 | show overlay → 設焦點 → 等待 → 移除監聽 → hide → resolve | 同左 |

### 4. 遷移策略

#### 4.1 UC-04 Modal A（import-flow-controller.js `promptImportMode`）

**現狀**：依賴外部注入的 DOM 元素（overlay/modal/buttons），手寫 focus trap + settle 邏輯。
**遷移**：
- constructor 不再接收 Modal A DOM 元素引用
- `promptImportMode()` 內部用 createDialog confirm 建立 DOM：
  ```javascript
  const dialog = createDialog({
    variant: 'confirm',
    title: '選擇匯入模式',
    message: '覆蓋模式會清空...合併模式保留...',
    actions: [
      { value: 'overwrite', text: '覆蓋（清空現有書庫）', variant: 'primary' },
      { value: 'merge', text: '合併（保留現有書庫）', variant: 'primary' },
      { value: null, text: '取消', variant: 'secondary' }
    ]
  })
  this._dialogContainer.appendChild(dialog.overlay)
  return dialog.open()  // resolve: 'overwrite'|'merge'|null
  ```
- 回傳型別不變：`Promise<'overwrite'|'merge'|null|symbol>`（DOM 缺失哨兵保留為 static check）
- 測試 DOM helper 改為不注入 Modal A HTML（由 createDialog 動態建立）

#### 4.2 UC-04 Modal B（import-flow-controller.js `confirmEmptyFileOverwrite`）

**遷移**：同 4.1 模式，actions 為 `[{value:'proceed', text:'確認清空', variant:'danger'}, {value:null, text:'取消', variant:'secondary'}]`。
回傳 `Promise<boolean>`（`result === 'proceed'`）。

#### 4.3 import-panel.js `_handleStaleData`

**現狀**：同步 `window.confirm(message)` → boolean。
**遷移**：
```javascript
const dialog = createDialog({
  variant: 'confirm',
  title: '資料過期確認',
  message: message,
  actions: [
    { value: 'confirm', text: '確認匯入', variant: 'primary' },
    { value: null, text: '取消', variant: 'secondary' }
  ]
})
document.body.appendChild(dialog.overlay)
const result = await dialog.open()
dialog.overlay.remove()
if (!result) { this.reset(); return }
```
- `_handleStaleData` 已是 async，無介面變更
- 測試從 mock `window.confirm` 改為 mock createDialog 或真實 DOM 互動

### 實作備註：§4.1 vs §5「不改 overview.html」的解法

Solution §4.1 原描述隱含「Modal A/B 從靜態 HTML 移除」，但 §5「不在範圍」明文列「不改
overview.html」。實測發現二者對測試層有直接衝突：createDialog 每次呼叫皆建立全新 DOM
node，若移除/替換既有靜態 node，既有測試中在呼叫前就 capture 的 stale DOM 參考會失效
（Esc/遮罩點擊等監聽器綁在新 node，舊參考收不到事件）。

最終採用方案（字面遵守「不改 overview.html」）：overview.html 與
overview-page-controller.js 完全不變；import-flow-controller.js 的
elements.importMode*/emptyFileConfirm* 5 個 DOM 引用降級為「DOM 是否已初始化」的
存在性防禦錨點（sentinel guard，因 import-flow-controller.test.js 有測試以 document:{}
注入驗證此路徑必須在呼叫 createDialog 前攔截，不可被移除）；guard 通過後實際互動
對話框由 createDialog 動態建立並掛載至 document.body，resolve 後即移除。

副作用：overview.html 內原 Modal A/B 巢狀子節點（title/desc/buttons）成為未使用死碼
（外層 overlay/modal 容器 id 仍作防禦錨點保留）。未在本 ticket 清理，如需移除建議另立
DOC ticket。E2E 測試相依性已記錄於 Spawn Requests SR-1。
