## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

create 的版本歸屬引導（`suggest_version_for_ticket`）與註冊驗證（`validate_version_registered`）讀 `get_project_root()/docs/todolist.yaml`。三個 create 流程測試檔以 `real_repo_root` fixture 將 CLAUDE_PROJECT_DIR 指回真實 repo（W1-054 設計，當時為解 VERSION_NOT_DETECTED），使測試綁定專案 todolist 的即時註冊狀態：專案版本推進後 patch 建議版本（1.3.2）未註冊，create 在待測錯誤路徑之前先 hard-fail VERSION_NOT_REGISTERED，預期 errno（CHECKLIST_VALIDATION_FAILED 等）永不出現。

### 影響範圍

- PC-162 重驗：票載 10 個失敗，今日 stash baseline 實測 **9 個**（環境依賴本質即隨專案狀態浮動，兩數字同一根因）：test_create_error_envelope.py 7 個 + test_create_ux_merged_validation.py 2 個。
- `real_repo_root` 全消費者盤點：三個 create 流程測試檔（含當日未失敗但同構脆弱的 test_error_channel_integration.py scenario_4）須轉 hermetic；test_claim_auto_tdd_phase / test_dispatch_recommender 不讀 todolist 註冊狀態（claim 流程 / registry 實檔載入），保留 real_repo_root 合理。

### 相關 Error Pattern

- PC-162（接手獨立重驗：10 → 9）；環境依賴測試屬 flaky 家族但非 race（確定性隨外部狀態翻轉），與 PC-168 取樣要求區隔——本案單次重現即確定。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
變更清單（4 檔，全在測試層，零 src 變更）：

| 檔案 | 變更 |
|------|------|
| .claude/skills/ticket/conftest.py | 新增 `seeded_repo_root` fixture：tmp root 種入受控 todolist.yaml（1.0.0 completed → patch 建議 1.0.1 命中 active 註冊；1.1.0 active + proposals 封 major 路徑），版本偵測三函式全走確定性資料；real_repo_root docstring 補使用邊界（僅限真實 repo 資產測試） |
| ticket_system/tests/test_create_error_envelope.py | 9 個測試簽名 real_repo_root → seeded_repo_root；檔頭註解更新 |
| ticket_system/tests/test_create_ux_merged_validation.py | 7 個測試簽名同上 |
| tests/test_error_channel_integration.py | scenario_4 同上（當日未失敗但同構脆弱，一併轉換） |

隔離證明：專案 todolist.yaml 當前即處「建議版本未註冊」狀態（失敗觸發條件成立中），轉換後測試通過——證明讀取來源已是種子檔而非專案檔（acceptance #2 的 fixture 隔離驗證）。
