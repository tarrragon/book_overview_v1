## Problem Analysis

### 分析範圍與方法

**問題**：ticket 系統以 Linux process 模型設計（ticket=process 承載資訊、ticket ID=PID、派發 agent=多線程、以 ID 為記錄核心），使用數月後需以實證回顧設計缺失。

**證據基礎（三源）**：
1. 量化：2285 張歷史 ticket 語料庫全量 grep 普查（見重現實驗結果）
2. 質性：289 個 error-pattern（PC 200 + IMP 89）、數月累積的 memory feedback（約 90 條，其中 ticket 系統相關約 40 條）
3. 結構：ticket CLI（39 子命令）、25 個 ticket skill hooks、settings.json 80 註冊 hooks

**方法**：Linux process 模型逐項對照（成立處/斷裂處）→ 每項缺失錨定實證 → WRAP 檢核關鍵判讀 → 改進方向 spawn 規劃。
