## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

APP spec §14.6 契約表（contract-version: v1）標記 8 個「v1 待建」元件項（card 三變體/dialog 二變體/badge 四變體按元件計 4 類），但 W6 建票時僅 divider 有對應票（W6-004）。缺口成因：PROP-013 In Scope 5 工作項聚焦「升格 + 契約對齊 + divider + manifest + 測試」，未含其餘待建元件的落地決策，形成契約承諾與 backlog 之間的追蹤空隙。

### 分析目標

逐一盤點 4 類待建元件在 v1 的實際消費場景（rg 實測，非推估），有場景者建 IMP 票、無場景者顯性豁免，消除「契約標了但無人追蹤」的死角。
