## 重現實驗結果
### 實驗方法

三層量測（PyYAML 解析全語料 frontmatter，腳本內嵌於本節可重現）：

1. **母體普查**：`docs/work-logs/**/tickets/*.md` 全量掃描，篩「when 為非空字串 AND 含 ticket ID 樣式（完整 `\d+\.\d+\.\d+-W\d+-\d+(\.\d+)*` 或短式 `W\d+-\d+(\.\d+)*`）AND blockedBy 空」。
2. **系統抽樣分類**：母體排序後每 15 筆取 1（61 筆，可重現），PM 逐筆依 When 文字分類「依賴語意」（X 完成後/驗收後/落地後/done 後）vs「出處/非依賴」（發現/案例/拆分後/spawn 落地後/並行標記/反向依賴/認領後）。
3. **建立時滿足度模擬**：對兩組分別解析 When 首個提及 ID（短式以自身版本補前綴），比對被提及票 completed_at 日期 vs 本票 created 日期，模擬「條件式 warn（提及票非 terminal 才警）」的真陽性/誤警分佈。

### 實驗執行

- 母體：**913 / 2285+ 票（約 40%）**，parse_fail=0。
- 抽樣分類：**依賴語意 35/61（57.4%）、出處/非依賴 26/61（42.6%）**。
- 依賴語意組滿足度：建立日前已完成=0、**同日=32**（follow-up 慣例：ANA 完成當日建後續票，建立時前置實質已滿足）、**建立時未完成=3**（0.18.0-W6-012.2.1 / 0.19.0-W1-003 / 0.19.0-W1-092——真漏標 blockedBy）。
- 出處組條件式 warn 模擬：**誤警 9/26**，結構性誤警源三類——母票 umbrella in_progress（如 W5-005.11 提及尚未收斂的母票）、並行標記（「與 X 並行」而 X 未完）、反向依賴（「X 派發前先做本票」）。

### 實驗發現

已驗證事實：

1. 無條件 warn（When 含 ID 且 blockedBy 空即警）：誤報 = (26 出處 + 32 已滿足) / 61 ≈ **95%**。
2. 條件式 warn（提及票非 terminal 才警）：精準度 = 3 / (3+9) = **25%**；誤警源為結構性（散文層無法可靠排除）。
3. 真實漏標率：3/61 ≈ **5%**（外推母體約 45 筆歷史漏標，多屬已收斂版本）；接手端已有補償 SOP（讀 When 全文人工補 blockedBy）。

限制（caveat）：滿足度以「日期」粒度近似（created 無時分秒），同日 32 筆無法逐筆證明時序；但「X 完成後」措辭 + 同日 + follow-up 建票慣例三者一致指向建立時已滿足，且即使全部改判未滿足，出處組 9 筆誤警已使條件式 warn 精準度不可用。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### WRAP 檢核

- **W（多元選項）**：四案並列——無條件 warn / 條件式 warn（提及票非 terminal 才警）/ auto-populate / 零機制慣例；另考慮混合案（僅對「完成後」措辭警）評估後併入條件式 warn 討論（措辭比對仍無法排除三類結構性誤警源）。
- **R（現實檢驗）**：不採假設推理，直接以 61 筆抽樣 + 建立時滿足度模擬取得誤報率實測（見重現實驗結果）。
- **A（拉開距離）**：warn 機制的 10/10/10——每次建票/接手多一則 75-95% 機率無效的提示，恰好複製 W5-005 F3 批判的「事後 hook 免疫系統增生」模式；本票的存在理由正是「未量測前不可上 warn」。
- **P（準備犯錯）**：若未來漏標率上升（如多人並行 PM 場景），重啟機制評估的訊號是接手端補 blockedBy 的頻率——已由既有接手 SOP 自然觀測，無需新監測票。

### 三選一裁定：零機制慣例（acceptance 2）

| 選項 | 實測 | 裁定 |
|------|------|------|
| 無條件 warn | 誤報約 95% | 否決 |
| 條件式 warn | 精準度 25%（3 真陽性 / 9 誤警，誤警源結構性） | 否決 |
| auto-populate | 43% 語意錯注入 + 52% 冗餘注入 | 否決 |
| **零機制慣例** | 真漏標率約 5% 且接手端補償 SOP 已存在 | **採納** |

**慣例落地**（`.claude/skills/ticket/references/field-semantics.md` v1.1.0，blockedBy 節新增「When 散文與 blockedBy 的邊界」）：When 為人讀時機敘事，工具不得從散文推斷依賴；真依賴建立時顯性 --blocked-by；出處用 --source-ticket；接手端發現 When 前提未編碼時人工 set-blocked-by 補齊。

**Trigger 綁定**（decision-trigger-binding 規則 1）：本裁定為狀態 (a) 已決策（零機制），無延後項；warn/auto-populate 不 spawn IMP（依 acceptance 2 條件分支，零機制路徑僅需慣例文件，已落地）。
