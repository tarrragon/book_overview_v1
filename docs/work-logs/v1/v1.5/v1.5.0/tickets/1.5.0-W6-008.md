## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作內容

1. **scripts/validate-token-manifest.js**：純函式核心（collectManifestTokens / flattenExports / loadV1TokenPaths / validateBidirectional）+ CLI 入口（main）。V1 token 檔以 require() 直接載入取值（未用 regex）。
   - 正向校驗：domains.*.tokens[] 內 platforms.v1 非 null 者，逐一比對 V1 原始檔實際值（deepEqual 支援 primitive 與 {fg,bg} 型淺層物件）。
   - 反向校驗：對 4 個 V1 檔（colors/shadows/spacing/typography.js）的 module.exports 攤平為 path→value 對照表，逐一確認每個 path 都出現在 manifest 的 platforms.v1.path 集合中。
   - 任一方向不符 exit 1，錯誤訊息分三類（正向不符 / 正向缺失 / 反向缺失），皆含具體修復指令。
2. **package.json**：新增 validate:token-manifest script。
3. **.github/workflows/lint.yml**：新增兩 step（Validate token manifest 與 Validate design system CSS），比照既有「Check no emoji」step 接法，接在 ESLint + emoji 檢查之後。同批修復孤兒腳本 validate:design-system（此前僅存在於 package.json，未接入 CI）。
4. **tests/unit/scripts/validate-token-manifest.test.js**：20 個測試案例，涵蓋純函式邏輯（deepEqual / flattenExports / collectManifestTokens 三種巢狀型態）、loadV1TokenPaths I/O（暫存 fixture 檔驗證 require() 載入）、validateBidirectional 正反兩向漂移偵測（含同批多項不符與 platformOnlyApp 排除案例），以及真實資料一致性 sanity check（跑真實 manifest + 真實 V1 檔應 0 errors）。

### W6-007 manifest 誤植發現與修正（校驗正當產出，非規劃外變更）

本機首次執行 npm run validate:token-manifest 時，正向校驗發現 3 筆真實漂移：

| domain | key | manifest 記載值（誤） | V1 實際值（正確） |
|---|---|---|---|
| shadowColors | sm | rgba(0,0,0,0.1) | rgba(0, 0, 0, 0.1) |
| shadowColors | md | rgba(0,0,0,0.25) | rgba(0, 0, 0, 0.25) |
| overlayColors | scrim | rgba(0,0,0,0.5) | rgba(0, 0, 0, 0.5) |

根因：W6-007 手動轉錄時漏了 rgba() 逗號後的空格。三筆皆已修正為與 V1 原始檔（shadows.js）一致的值，修正後複查 62 項正向 + 62 項反向查核全數通過。此修正屬 ticket 約束「manifest 僅在校驗發現 W6-007 產出有誤時才可修」的正當範圍，未觸碰 V1 token 檔本身。
