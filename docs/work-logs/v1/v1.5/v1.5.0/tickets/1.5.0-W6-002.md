## Problem Analysis

### 問題根因

ui-factory.js 位於 src/popup/components/，僅 popup 面可用；PROP-013 工作項 1 要求升格為全 Extension 共用元件庫（src/core/ui/components/）。blockedBy W6-001 已解除（樣式收斂完成，class 規則已入 component-rules.js）。

### 影響範圍（PM 前置驗證 2026-07-12）

**引用盤點（PC-162 獨立驗證）**：
- src require 引用 2 處：popup.js L131 `require('src/popup/components/ui-factory')`、popup-ui-components.js L29 同路徑 require
- src 註解/文件引用：popup.html L71/L152（註解）、constants/bookstore-config.js L5（註解）
- tests 4 檔：popup-button-factory-usage.test.js、popup/bookstore-nav.test.js、popup/ui-factory.test.js、popup/popup-ui-components.test.js
- **overview 現況零引用**——acceptance 2「popup 與 overview 皆引用同一核心元件庫」解讀為：所有既有引用點統一指向新核心路徑；新增 overview 消費屬 PROP-013 後續工作項，不在本票範圍（AC 語意記錄，PC-055）

**路徑解析機制（搬遷無需改設定）**：
- Jest：package.json moduleNameMapper `^src/(.*)$` → rootDir/src（generic）
- esbuild：scripts/build.js bundleEntryPoints `alias: { src: BUILD_DIR/src }`（generic）
- 結論：僅需改 require 字串為 `src/core/ui/components/ui-factory`，兩解析層自動生效

**同步清單**：
- src/core/ui/ 目錄不存在，需新建 src/core/ui/components/
- ui-factory.js 檔頭 docstring stale：「class 名稱與 popup.html 既有 <style> 完全一致」已因 W6-001 改為 component-rules.js 來源，搬遷時一併更新
- CLAUDE.md §6.1 L138 路徑表引用 `src/popup/components/ui-factory.js`，搬遷後需同步（DOC 同步納入本票或依規模 spawn）
- tests/unit/popup/ui-factory.test.js 檔案位置是否隨遷至 tests/unit/core/ 由執行代理人依測試目錄慣例裁定並記錄

### 簡化 WRAP 三問

- W：(a) 純搬遷 + require 路徑修正（採用，how.strategy 既定）；(b) 搬遷同時新增 overview 消費端（範圍蔓延，PROP-013 後續工作項，否決）；(c) 保留原檔 re-export shim 過渡（acceptance 3 明令原檔移除，否決）。
- A：搬遷屬機械性變更，不擠壓 W6-013 等後續票。
- P：最可能失敗＝遺漏字串引用點（註解/文件內路徑）致 grep 驗證不過或文件漂移。防護：上方同步清單已窮舉 grep -rln 結果；acceptance 2 以 grep 驗證統一性。

### 搬遷實作（2026-07-12, general-purpose）

**git mv 保留歷史**：
- `src/popup/components/ui-factory.js` → `src/core/ui/components/ui-factory.js`（新建 src/core/ui/components/）
- `tests/unit/popup/ui-factory.test.js` → `tests/unit/core/ui/components/ui-factory.test.js`

**測試檔位置裁定**：tests/unit/ 目錄結構鏡像 src/（tests/unit/core/ 既存且子目錄與 src/core/ 對應），故 ui-factory.test.js 隨遷至 tests/unit/core/ui/components/，require 改相對路徑 `../../../../../src/core/ui/components/ui-factory`。bookstore-nav.test.js 屬 popup 導航功能測試，留在 tests/unit/popup/，僅改 require 為 `../../../src/core/ui/components/ui-factory`。

- popup.js L131：`require('src/core/ui/components/ui-factory')`
- popup-ui-components.js L29：同路徑。jest moduleNameMapper `^src/(.*)$` 與 esbuild alias 皆 generic，零設定變更（PM 前置驗證成立）。

**註解/文件同步**：
- popup.html L152 註解路徑更新（L71 與 bookstore-config.js L5 僅泛稱「ui-factory」無路徑，語意仍正確，不改）
- ui-factory.js 檔頭 docstring 更新：定位改「全 Extension 共用 UI 元件工廠」，class 來源改 `src/core/design-system/component-rules.js`（修正 W6-001 後 stale 的「popup.html 既有 <style>」表述）
- ui-factory.test.js 檔頭同步 class 來源表述

**AC2 語意執行**：僅統一既有引用點（popup 面 2 處 require + 2 測試 require）指向核心路徑；未新增 overview 消費端（src/overview/overview-page-controller.js 的 createElement('button') 直建屬 PROP-013 後續工作項範圍，不在本票處理）。
