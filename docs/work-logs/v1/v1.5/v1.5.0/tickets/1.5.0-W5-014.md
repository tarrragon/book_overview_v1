## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

Confabulation 是 LLM 自回歸生成的數學行為（PC-166 L1-L3），不是工具呼叫行為。現有 6 層防護（A-F）全為規則層自律。W5-011.3 證實：即使規則存在，連驗證步驟的 stdout 也會被虛構（遞歸污染），規則層在高 tool-call 密度序列中失效。

核心矛盾：confabulation 是「模型不發工具呼叫而續寫預期結果」——恰好發生在 hook 系統盲區（hook 只能攔截實際的工具呼叫，不能攔截「模型沒有呼叫工具卻寫出看似工具結果的文字」）。

### 影響範圍

- `.claude/rules/core/tool-output-trust-rules.md`（規則 1-5，規則層自律）
- `.claude/error-patterns/process-compliance/PC-166-*.md`（防護 A-F）
- 所有涉及 mutation → 驗證的工作流（commit / complete / append-log / set-*）

### 相關 Error Pattern

- PC-166（confabulated tool result，6 層防護 A-F）
- PC-111（決策論述捏造技術機制）
- PC-147（reference doc confabulation cascade）

## 重現實驗結果
### 實驗方法

盤點 CC hook 事件類型與 confabulation 生成行為的交集，判斷 hook 能否攔截虛構文字生成。

### 實驗執行

**步驟 1：CC hook 事件類型盤點**

本專案已註冊的 hook 事件：
- PreToolUse: 11 hooks（工具呼叫前觸發）
- PostToolUse: 6 hooks（工具呼叫後觸發）
- SessionStart: 1 hook
- UserPromptSubmit: 1 hook
- SubagentStop: 1 hook
- Stop: 1 hook

CC 平台支援的全部事件（來源：claude-code-guide agent 知識）：
PreToolUse / PostToolUse / Stop / SubagentStop / SessionStart / SessionEnd / UserPromptSubmit / PreCompact / Notification

**步驟 2：Confabulation 生成行為分析**

Confabulation 的點火動作（PC-166 防護 F）：「工具呼叫發出後，在同一訊息續寫該工具的預期結果」。

此行為的本質是：模型在 tool_use 之後、下一個 tool_result 注入之前，繼續生成 text tokens。這是**模型生成行為**，不是工具呼叫行為。

**步驟 3：交集分析**

| Hook 事件 | 觸發時機 | 能否偵測 confabulation |
|-----------|---------|----------------------|
| PreToolUse | 工具呼叫前（有工具呼叫才觸發） | 否——confabulation 是「不呼叫工具卻寫結果」 |
| PostToolUse | 工具呼叫後（有工具呼叫才觸發） | 間接可能——可在 mutation 工具後注入驗證提示 |
| Stop | agent 結束時 | 事後審計——可驗證 claimed vs actual 狀態 |
| UserPromptSubmit | 用戶提交 prompt 時 | 否——不涉及模型生成行為 |
| PreCompact | context 壓縮前 | 否——不涉及工具結果 |

### 實驗發現

**已驗證事實**：
1. CC hook 系統無「AssistantTextGeneration」事件——hook 不能攔截模型的文字生成過程
2. confabulation 恰好發生在 hook 盲區（模型不發工具呼叫的時間窗口）
3. PostToolUse 是唯一可間接介入的事件（在真實工具呼叫後注入提示），但模型是否遵從提示仍屬自律層
4. Stop hook 可做事後審計（claimed mutations vs git ground truth），但無法預防

**仍未驗證的假設**：
- CC runtime 未來是否可能新增 AssistantMessage / TextGeneration 事件（需追蹤 CC release notes）
- PostToolUse 注入驗證提示的實際效果（是否比規則層更可靠——假設需實驗驗證）
