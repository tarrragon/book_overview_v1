## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

Confabulation 是 LLM 自回歸生成的數學行為（PC-166 L1-L3），不是工具呼叫行為。現有 6 層防護（A-F）全為規則層自律。W5-011.3 證實：即使規則存在，連驗證步驟的 stdout 也會被虛構（遞歸污染），規則層在高 tool-call 密度序列中失效。

核心矛盾：confabulation 是「模型不發工具呼叫而續寫預期結果」——恰好發生在 hook 系統盲區（hook 只能攔截實際的工具呼叫，不能攔截「模型沒有呼叫工具卻寫出看似工具結果的文字」）。

### 影響範圍

- `.claude/rules/core/tool-output-trust-rules.md`（規則 1-5，規則層自律）
- `.claude/error-patterns/process-compliance/PC-166-*.md`（防護 A-F）
- 所有涉及 mutation → 驗證的工作流（commit / complete / append-log / set-*）

### 相關 Error Pattern

- PC-166（confabulated tool result，6 層防護 A-F）
- PC-111（決策論述捏造技術機制）
- PC-147（reference doc confabulation cascade）
