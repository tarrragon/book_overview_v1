### 實作策略

**1. ui-factory.js — 新增 createInput**

常數（對齊 BADGE_VARIANTS 風格）：
```js
const INPUT_TYPES = ['text', 'search']
```

函式簽名：
```js
function createInput ({ type = 'text', id, placeholder, ariaLabel, className } = {})
```
- 建立 `<input>` 元素
- class: `input input--{type}`
- 設 type/id/placeholder/aria-label 屬性
- type 不在清單內 throw（對齊 createBadge/createButton 模式）
- 加入 module.exports + window.PopupUIFactory

**2. component-rules.js — 新增 input 規則**

- `.input` 基礎：padding 用 spacing token（xs/sm），border-radius 用 radius token，font-size 用 typography token；border 用 inset token（`--shadow-inset` 或 `--color-border`）
- `.input--search`：可加 search 圖示 padding-left 預留（或與 text 共用基礎）

**3. overview.html L29 — 移除硬編碼 input**

移除 `<input type="text" id="searchBox" placeholder="搜尋書籍標題...">`，保留容器（如有）。searchBox 改由 JS 動態插入。

**4. overview-page-controller.js — 動態建立 searchBox**

在 init/setup 階段用 createInput 建立並插入 DOM：
```js
const searchBox = createInput({
  type: 'search',
  id: 'searchBox',
  placeholder: GlobalMessages.OVERVIEW.SEARCH_PLACEHOLDER,
  ariaLabel: '搜尋書籍'
})
```
- placeholder 引用 l10n key（需在 GlobalMessages 或 popup/constants/ui-text.js 新增 SEARCH_PLACEHOLDER 常數）
- L210 的 DOM 選擇器宣告可能需調整（從 HTML 靜態查找改為引用動態建立的元素）
- L274-275 事件綁定和 L1310-1311 resetSearch 邏輯保持不變

**5. l10n key**

在適當的 messages 常數檔新增：
```js

```
