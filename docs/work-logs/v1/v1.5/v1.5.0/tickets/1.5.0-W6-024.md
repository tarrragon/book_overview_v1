## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

契約 §14.6 標 AppTextField.text/search ↔ createInput v1 待建。overview.html L29 的 searchBox 是硬編碼 `<input type="text" id="searchBox" placeholder="搜尋書籍標題...">`，未走 ui-factory 工廠函式，placeholder 硬編碼中文非 l10n key。

### 影響範圍

- `src/core/ui/components/ui-factory.js` — 新增 createInput + INPUT_TYPES 常數
- `src/core/design-system/component-rules.js` — 新增 .input 基礎 + .input--search 規則（inset token）
- `src/overview/overview.html` — searchBox 硬編碼 input 移除（改由 JS 動態建立）
- `src/overview/overview-page-controller.js` — searchBox 改用 createInput 動態建立
- overview.css — 無 searchBox 相關樣式（已確認 grep 無命中）

### 現有消費點分析

overview-page-controller.js 中 searchBox 引用 4 處：
- L210：DOM 選擇器宣告 `search: ['searchBox']`
- L274-275：addEventListener 'input' 綁定搜尋邏輯
- L1310-1311：resetSearch 清空 value

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作內容

1. `src/core/ui/components/ui-factory.js`：新增 `INPUT_TYPES = ['text', 'search']`
   + `createInput({type='text', id, placeholder, ariaLabel, className})` 純
   DOM 函式（對齊 createBadge/createButton 模式：type 不在清單內 throw）。
   **設計決策**：DOM 原生 `type` 屬性固定為 `text`，search/text 型別區分完全
   透過 `input--{type}` CSS class 表達，不使用原生 `type="search"`——原生
   search type 會帶出瀏覽器內建清除按鈕（webkit-search-cancel-button），
   會改變既有視覺與可能影響既有測試對 `.value`/DOM 結構的假設，故以 CSS
   語意區分取代原生行為區分。已加入 module.exports 與 window.PopupUIFactory。

2. `src/core/design-system/component-rules.js`：新增
   - `.input` 基礎規則：width/padding/border/border-radius/font-size/color/
     background 皆引用 CSS custom properties token
   - `.input:focus`：outline 移除 + border-color 換 primary token
   - `.input--search`：v1 暫無 icon 消費場景，沿用 `.input` 基礎樣式，class
     區分僅供契約型別語意與未來擴充預留
   - **inset token 處理**：design-system-spec.md §8.3 石碑刻痕效果定義
     `inset`（凹陷，用途：選中/按下狀態），但專案尚無獨立產生的
     `--shadow-inset` CSS 變數（僅為 spec 概念，未落地為 token）。改借用
     既有 `--shadow-color-sm` 搭配 CSS `inset` 關鍵字（`box-shadow: inset 0 1px 2px var(--shadow-color-sm)`）
     呈現凹陷語意，不新增未定義 CSS 變數。

3. `src/overview/overview.html`：L29 移除硬編碼
   `<input type="text" id="searchBox" placeholder="搜尋書籍標題...">`，改為
   `<div id="searchBoxContainer"></div>` 空容器掛載點。

4. `src/overview/overview-page-controller.js`：
   - 新增 `_ensureSearchBox()` 方法：DOM 已存在 `#searchBox`（測試 fixture
     常見模式：以 innerHTML 直接建置整組靜態元素）則略過建立，維持既有測試
     100% 相容，**無需逐一調整任何測試 setup**；`#searchBoxContainer`
     不存在時同樣略過，行為與遷移前一致（無搜尋框）
   - 於 constructor 內 `initializeElements()` 之前呼叫 `_ensureSearchBox()`，
     確保 `getElementById('searchBox')` 查找順序正確（ticket 提醒的 init
     順序風險已處理）
   - `CONSTANTS.MESSAGES.SEARCH_PLACEHOLDER` 新增為 l10n key 唯一來源
     （沿用本檔既有 `CONSTANTS.MESSAGES` 局部常數慣例，非引入新的
     GlobalMessages 系統——本檔尚未採用該系統，最小化改動風險）
   - L210/L274-275/L1310-1311 既有 searchBox 消費邏輯（DOM 選擇器宣告 /
     事件綁定 / resetSearch）完全不變，因 `_ensureSearchBox()` 確保
     `#searchBox` 在這些邏輯執行前已存在於 DOM

5. **範圍外必要追加**（W6-023 先例）：`tests/unit/helpers/popup-migrated-selectors.js`
   （原 ticket where.files 未列此檔）—popup-style-scope.test.js 的 B1 雙向
   全等守護要求 COMPONENT_RULES 新增選擇器同步登記，新增 input 3 條
   （`.input` / `.input:focus` / `.input--search`），並更新檔頭統計註解
   （45→48 條）。

6. `design-system.css` 已執行 `node scripts/generate-design-system-css.js`
   重新產生。過程中發現並修正一處注釋文字副作用：CSS 註解內文字換行後
   `--shadow-inset` 恰好落在行首，被 design-system-css-snapshot.test.js
   的樸素掃描（`line.trim().startsWith('--')`）誤判為變數宣告行而斷言失敗；
   已調整註解斷行方式避免任何行首出現 `--`（非變數宣告誤判，純文字排版
   調整，不影響語意）。
