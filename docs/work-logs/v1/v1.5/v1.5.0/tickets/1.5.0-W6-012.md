### 問題根因

component-rules.js L175-180（`.progress-bar`）與 L182-187（`.progress-fill`）宣告逐字相同（height:100% / background:var(--color-primary) / border-radius:var(--radius-xs) / transition:width .3s）。pre-existing，W6-001 遷移時逐字搬運未改寫。

### 影響範圍（PM 前置驗證 2026-07-12）

- 兩 class 均活躍使用，**禁止刪除任一**：`.progress-bar` 為容器（popup-ui-components.js L173 querySelector、ui-progress-handler.js L418 等）；`.progress-fill` 為內層填充（popup.js L473 `progressBar.querySelector('.progress-fill')`、popup-ui-components.js L164）。清理方向為合併群組選擇器 `.progress-bar,\n.progress-fill { ... }`（渲染語意不變）或代理人分析後之等效方案。
- **與 W6-011 新守護的互動（關鍵）**：B1 案例（popup-style-scope.test.js）以 `parseTopLevelSelectors(COMPONENT_RULES)` 全等斷言 MIGRATED_SELECTORS。合併為逗號群組後解析結果取決於 helper 對群組選擇器的處理語意——實作前先讀 tests/unit/helpers/popup-migrated-selectors.js 的 `parseTopLevelSelectors`，必要時同步 helper/清單（此為 B1 守護設計內行為，同步變更需記入 Solution）。

### 簡化 WRAP 三問

- W：(a) 合併群組選擇器（採用方向，保留兩 class）；(b) 刪其一並改 DOM/JS（越界——src 變更限 component-rules.js，否決）；(c) 裁定非債務維持現狀（Phase 4 已裁定 F1 為真實清理債，否決）。
- A：單點清理，不擠壓 W6 其他票。
- P：最可能失敗＝合併後 B1/S2 對群組選擇器解析語意不符致紅燈或漏網。防護：先讀 parseTopLevelSelectors 再動手；三態截圖比對防視覺回歸。
