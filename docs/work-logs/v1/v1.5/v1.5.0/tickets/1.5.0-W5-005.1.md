## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

直接原因：ticket 寫入路徑零枚舉驗證，實測三層開口——

1. CLI 參數層：`create.py --type`/`--priority` 無 argparse `choices=`（create.py:1228-1230），僅 help 文字宣告合法值；`track.py` set-priority 的 value 位置參數同樣無 choices（choices 僅用於 close reason 與 --format）。
2. 落盤層：`execute_set_field` 直接 `ticket[field] = new_value` 後 `save_ticket`（fields.py:226,230）；`save_ticket`（parser.py:284）純序列化，無任何 invariant 檢查。
3. 正典層：枚舉宣告分裂——`constants.py` TICKET_TYPES 7 型 vs `_TYPE_REQUIRED_SECTIONS` 僅定義 ANA/IMP/DOC vs 母票普查口徑 4 型正典；章節名清單兩處異本（VALID_SECTIONS 10 章 vs SCHEMA_H2_SECTIONS 9 章，且 Context Bundle 位置順序不同）。

根因（母票 F3）：無 kernel——invariant 不在寫入邊界強制，一致性靠事後 hook 免疫系統，同一類錯誤（枚舉漂移）在 type/priority/status/章節名四處各自重複發生。

### 影響範圍

- 寫入點：`save_ticket` 呼叫點實測 **31 處 / 12 檔**（母票估「約 15」為低估，PC-162 重驗）：fields.py 5、lifecycle.py 5、track_acceptance.py 4、track_relations.py 4、migrate.py 2、version_shift.py 2、file_lock.py 2、create/generate/bulk_create/track_batch/track_set_acceptance/ticket_builder/context_bundle_extractor 各 1。
- 語料庫既成漂移（母票普查 + 審查修正口徑）：type 12 筆、priority 約 24 筆、status skipped 6 筆、章節名 77 筆。
- 消費端：runqueue priority 主排序鍵、dashboard、td-status、以 yaml.safe_load 讀 frontmatter 的 14/24 hook。
- 既有防護地圖：frontmatter Edit 路徑已被 `ticket-file-access-guard-hook` 全面阻擋（Edit frontmatter → exit 2）；CLI 寫入路徑是唯一無驗證開口；章節名漂移來自 guard 允許的 body Edit 通道。

## 重現實驗結果
### 實驗方法

以現行 CLI 對本票（已認領、可回復）寫入非法 priority 值 `P9`（普查中真實存在的漂移值），觀察是否被任何層攔截；grep frontmatter 驗證落盤；再回復 `P1`。輔以靜態盤點：save_ticket 呼叫點全量、argparse choices 使用點、TICKET_TYPES 消費端。

### 實驗執行

1. `ticket track set-priority 1.5.0-W5-005.1 P9` → exit 0，stdout「已更新 新值: P9」
2. `grep "^priority:" <ticket md>` → `priority: P9`（非法值原樣落盤）
3. `ticket track set-priority 1.5.0-W5-005.1 P1` → exit 0 回復；grep 確認 `priority: P1`
4. `grep -rn "save_ticket(" ticket_system --include="*.py"`（排除 tests/docstring）→ 31 呼叫點 / 12 檔
5. `grep -n '"--type"|"--priority"|choices=' create.py track.py` → --type/--priority 無 choices；choices 僅 close reason 與 --format
6. `grep -rn "TICKET_TYPES" ticket_system`（排除 tests）→ 消費端僅 tdd_sequence import 與 ticket_builder 註解引用

### 實驗發現

已驗證事實：
- CLI 端到端接受非法枚舉值，零警告零阻擋 exit 0——F3「寫入時零驗證」根因成立。
- 正典素材已存在但分裂：constants.py 有 TICKET_TYPES(7)/PRIORITY_LEVELS(4)/TICKET_STATUS(6)；缺的是強制與三方對齊，不是從零建 SSOT。
- frontmatter Edit 路徑已被 ticket-file-access-guard-hook 阻擋，CLI 路徑是唯一無驗證開口。
- TICKET_TYPES 收斂 blast radius 小（消費端輕量）。

- warn 模式誤報率（由量測子票承載）。
