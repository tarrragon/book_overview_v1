### 問題根因

直接原因：ticket 寫入路徑零枚舉驗證，實測三層開口——

1. CLI 參數層：`create.py --type`/`--priority` 無 argparse `choices=`（create.py:1228-1230），僅 help 文字宣告合法值；`track.py` set-priority 的 value 位置參數同樣無 choices（choices 僅用於 close reason 與 --format）。
2. 落盤層：`execute_set_field` 直接 `ticket[field] = new_value` 後 `save_ticket`（fields.py:226,230）；`save_ticket`（parser.py:284）純序列化，無任何 invariant 檢查。
3. 正典層：枚舉宣告分裂——`constants.py` TICKET_TYPES 7 型 vs `_TYPE_REQUIRED_SECTIONS` 僅定義 ANA/IMP/DOC vs 母票普查口徑 4 型正典；章節名清單兩處異本（VALID_SECTIONS 10 章 vs SCHEMA_H2_SECTIONS 9 章，且 Context Bundle 位置順序不同）。

根因（母票 F3）：無 kernel——invariant 不在寫入邊界強制，一致性靠事後 hook 免疫系統，同一類錯誤（枚舉漂移）在 type/priority/status/章節名四處各自重複發生。

### WRAP 檢核

**W（候選方案）**：A（採用）三層閘——argparse choices（參數邊界 fail-fast）+ save_ticket 驗證閘（31 寫入點單點收斂）+ lifecycle 轉移矩陣，warn 先行。B 僅 argparse choices——擋不住 CLI 內部邏輯產生的非法值（create --parent 版本繼承 bug 即活體案例），且 set-* 泛用 value 無法全 choices 化，否決為單獨方案、保留為 A 的第一層。C 事後 hook 掃描強化（現狀模式）——母票 WRAP 10/10/10 已論證 hook 數隨欄位數線性增生，否決。D 刪除性方案（刪 priority/降 binary flag，母票 Alt 發現 4）——priority 是 runqueue 主排序鍵、P0-P3 已被 scheduler/dashboard 消費，重寫消費端成本 > 驗證閘，否決但記錄於設計空間。
**R（現實檢驗）**：成熟 tracker 寫入時驗證是基本率（Jira/Linear API 422、DB constraint）；本設計對齊基本率，非發明新機制。
**A（機會成本）**：閘為每次寫入加 O(3) 鍵比對 + snapshot 淺複製，效能可忽略；真成本是 warn 期誤報噪音，以量測子票管理。
**P（最可能失敗）**：化石豁免實作錯誤——若做成「全票驗證」，2285 歷史票任何欄位操作都炸警告（對含 P9 的化石票 append-log 即觸發）。防護：changed-fields-only 為 acceptance 硬條件 + 測試案例指名（見下）。

### 一、枚舉 SSOT 宣告（step 0：三方對齊裁定）

正典位置：`ticket_system/constants.py`（既有常數升格為唯一權威；文件層 ticket-body-schema.md / SKILL.md 引用之，不重複宣告值）。

| 枚舉 | 三方現況 | 收斂裁定 |
|------|---------|---------|
| type | constants 7 型 vs body schema 僅 ANA/IMP/DOC 有章節定義 vs 普查口徑 4 型 | **收斂為 4 型 IMP/ANA/DOC/ADJ**。TST（0 使用，職能被 tdd_phase 吸收）、RES（0 使用，被 ANA 吸收）、INV（3 筆化石，被 ANA 吸收）移出正典。INV 合法性歧義裁定：不合法，3 筆化石豁免。create.py help / SKILL.md / body-schema.md 同步 |
| priority | 三方一致 P0-P3 | 維持 P0-P3；漂移約 24 筆化石豁免 |
| status | constants 6 態；語料另有 skipped 6 筆 | 維持 6 態（pending/in_progress/completed/blocked/superseded/closed）；skipped 不擴枚舉（語意由 closed + close_reason 承載），化石豁免 |

新增常數：`VALID_TICKET_TYPES` / `VALID_PRIORITIES` / `VALID_STATUSES`（frozenset）、`STATUS_TRANSITIONS`（轉移矩陣）、`CANONICAL_BODY_SECTIONS`、`ENUM_GATE_MODE = "warn"`。

### 二、CLI 端封口（argparse choices=）

create.py `--type`/`--priority` 加 `choices=`；track.py set-priority value 加 `choices=PRIORITY_LEVELS`。錯誤在參數解析層即報（argparse 標準 exit 2 + usage），為 fail-fast UX 層，非完整防護。

### 三、save_ticket 驗證閘（主體）

- 機制：`load_ticket` 時掛 `_loaded_enum_snapshot`（type/priority/status 三鍵原值；`_` 前綴欄位既有備份恢復機制可沿用）；`save_ticket` 落盤前呼叫 `validate_enum_gate(ticket)`：
  - 欄位值 == snapshot → 跳過驗證（**化石豁免自動達成**：舊票非法值未被本次操作觸碰即不驗）
  - 欄位值 != snapshot 或無 snapshot（新建票）→ 驗證新值屬 VALID_*
  - status 變更額外查 `STATUS_TRANSITIONS[old]` 是否含 new
- warn 模式：違規 → stderr 警告 + 照常落盤 + append `.claude/hook-logs/enum-gate.log`（時間戳/ticket id/欄位/舊值/新值/入口命令）供量測。
- deny 模式：違規 → raise EnumGateViolation → 呼叫端 exit 非 0、不落盤。
- 覆蓋面：31 呼叫點全收斂於 save_ticket 單點；frontmatter Edit 路徑已由 ticket-file-access-guard 阻擋，不重複驗證。

### 四、lifecycle 狀態轉移驗證強化

轉移矩陣初稿（實作票細化，per-command guard 保留為語意層、閘為兜底層）：
pending → in_progress / blocked / closed；in_progress → completed / pending / blocked / closed；blocked → pending / in_progress / closed；completed → superseded（唯一出邊，是否開放由實作票裁定）；closed / superseded → terminal 無出邊。

### 五、驗證閘測試案例（acceptance #2 指名，Never break userspace）

1. 化石豁免：載入 priority 為 P9 的既有票 → append-log / set-what（不碰 priority）→ 不觸發 warn/deny。
2. changed-only：同票 set-priority 為另一非法值 → 觸發。
3. 合法寫入：set-priority P1 → 無警告落盤。
4. 新建票：create --type INV → argparse 層擋；繞過 CLI 直呼 builder 塞非法 type → 閘擋。
5. 轉移矩陣：completed 票未經 release 直接改 pending → 觸發。
6. warn / deny 模式切換行為各自驗證。

### 六、warn → deny 升級 trigger（acceptance #3）

綁定量測子票（見下表 .4）：warn 模式運行一個 Wave 後統計 enum-gate.log——誤報率（合法操作被警告比例）< 5% 且無阻斷性案例，為 deny 切換 trigger；不符則修閘後重測。禁時間式延後（decision-trigger-binding 規則 2）。
