## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 決策：修 helper（非拋出式錯誤注入），非改測試 try/catch

理由：12 test 對 errorSimulator 的呼叫模式高度分散（直接 await、陣列 callback、`error: () => ...`
形式），且逐一 try/catch 包裹改動點多、易漏；相較之下 ErrorSimulator 統一改為非拋出、回傳描述性物件
成本低且一致。同時確認 `chrome-extension-controller.js` 從未讀取 `ErrorSimulator` 的任何內部狀態
（`grep -n "errorSimulator" tests/helpers/e2e-test-suite.js tests/helpers/chrome-extension-controller.js`
零命中），故 ErrorSimulator 拋出與否對 `waitForErrorState` 等方法完全不影響。

### 已完成變更

- `tests/helpers/error-simulator.js`：新增私有方法 `#buildSimulatedError()` 統一產生非拋出式錯誤
  描述物件（含 log 副作用），所有 `simulate*` 方法改為 return 而非 throw；新增測試呼叫但原本缺失的
  方法：`clearError` / `clearInterruption` / `corruptStorageData` / `freeStorageSpace` /
  `restoreNetwork` / `restoreNetworkConnection` / `restorePermissions` /
  `revokeExtensionPermissions` / `simulatePermissionRevocation`。

### 發現：根因比 ticket 描述更深，範圍超出本票 where.files

移除 `describe.skip` 並執行後，仍有 11/12 test 失敗（非 ErrorSimulator 契約問題）：

1. `chrome-extension-controller.js` 缺少 4 個測試依賴的方法：`waitForErrorWithDiagnostics` /
   `waitForErrorDisplay` / `waitForErrorWithGuidance` / `waitForErrorAndRecover`（TypeError: not a function）
2. 既有 `waitForErrorState` 的 canned 回傳未涵蓋 `solutionOptions` / `automaticRetryDisabled` /
   `recoveryPossible` 等測試斷言欄位
3. `errorSimulator` 與 `extensionController` 完全解耦，`clickExtractButton` 等方法不讀取
   errorSimulator 注入的錯誤狀態，導致「模擬中斷後應失敗」類斷言（`interruptionResult.success`
   應為 false 卻為 true）無法通過

此範圍屬 `chrome-extension-controller.js`（~3800 行既有 mock 狀態機），未列於本票
`where.files`，且工作量遠超本票（P3 低優先級）合理範疇，故保留 `describe.skip`（更新 TODO 註解
記錄精確缺口），並以 add-spawn-request 追蹤（SR-1）建議建立後續 Ticket 補齊 mock 契約。
