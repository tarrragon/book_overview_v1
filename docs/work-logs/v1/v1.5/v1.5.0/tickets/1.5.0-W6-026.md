## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因
ErrorSimulator 的 `simulate*` 方法直接 `throw`（同步拋出），但 12 個測試以 `await scenario.simulate()`
形式呼叫、未包 try/catch，導致例外向上傳播使測試失敗；同時測試引用了原檔案不存在的 9 個方法
（clearError/clearInterruption/corruptStorageData/freeStorageSpace/restoreNetwork/
restoreNetworkConnection/restorePermissions/revokeExtensionPermissions/simulatePermissionRevocation）。

### 影響範圍
`tests/helpers/error-simulator.js`（已修改）、`tests/integration/workflows/error-recovery-workflow.test.js`
（TODO 註解更新）。診斷過程另發現 `tests/helpers/chrome-extension-controller.js` 與
`tests/helpers/e2e-test-suite.js` 有更大範圍的 mock 缺口（見 Solution）。

### 相關 Error Pattern
PC-APP-001（trigger 票完成但覆蓋未落地）—— 0.15.0-W1-002 當時僅記錄 TODO，未實際修復，
本票驗證了根因判斷正確但範圍遠大於原 TODO 描述。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 決策：ErrorSimulator 重構（非測試改寫）+ 範圍發現後 spawn follow-up

**已完成**：`tests/helpers/error-simulator.js` 重構為非拋出式錯誤注入——所有 `simulate*` 方法
改為記錄 `activeError`/`simulatedErrors` 並正常 resolve（而非 throw），新增 12 test 引用但原檔缺失
的方法：`clearError`、`clearInterruption`、`corruptStorageData`、`freeStorageSpace`、
`restoreNetwork`、`restoreNetworkConnection`、`restorePermissions`、`revokeExtensionPermissions`、
`simulatePermissionRevocation`。此為 acceptance 條 1 的落地方案（二擇一：非拋出式注入）。

**範圍發現**：移除 skip 後實測，11/12 test 仍失敗，根因非 ErrorSimulator，而是
`tests/helpers/chrome-extension-controller.js`（5430 行 mock）缺少約 10 個測試依賴的方法
（waitForErrorDisplay / waitForErrorWithDiagnostics / waitForErrorWithGuidance /
waitForErrorAndRecover / getResumeOptions / resumeFromLastCheckpoint / getOperationLogs /
getRetryOptions / waitForNetworkRecovery，另 `e2e-test-suite.js` 缺 navigateToRestrictedPage /
injectCorruptedBookData），且 `clickExtractButton` 目前非狀態化模擬（呼叫當下立即依既有
storage 狀態回傳，無法反映「操作進行中途注入錯誤」的時序契約）。此範圍超出本票
`where.files`（僅宣告 error-simulator.js + 測試檔兩個檔案），屬需獨立規劃的較大重構。

**處置**：依規則 5/6（發現即追蹤、不回退既成工作），已用
`ticket track add-spawn-request` 記錄 follow-up（SR-1），描述具體缺口清單供後續 ticket 落地；
describe.skip 保留但更新 TODO 註解反映正確根因（原註解誤指向 ErrorSimulator，已修正）。

**驗收條件達成狀況**：
- [x] ErrorSimulator 支援非拋出式錯誤注入（acceptance 1 已達成）
- [ ] describe.skip 移除且 12 test 全數通過（未達成，範圍超出本票聲明的 where.files，已 spawn follow-up）
