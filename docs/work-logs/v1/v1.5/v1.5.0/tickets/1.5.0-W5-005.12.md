### Agent Type 能力矩陣

根據 `.claude/agents/*.md` frontmatter 與 CC runtime 行為，agent 的檔案寫入能力由兩個維度決定：

| 維度 | 值 | 說明 |
|------|-----|------|
| permissionMode | bypassPermissions / acceptEdits / 無 | 決定 Edit/Write 工具是否可用 |
| tools frontmatter | 是否含 Bash | 決定 heredoc 重導向是否可用 |

#### 完整矩陣（29 個實質 agent）

| 能力等級 | 代表 agents | Edit/Write | Bash heredoc | 交付通道 |
|---------|-------------|:----------:|:------------:|---------|
| L3 完全寫入 | thyme-python-developer, thyme-extension-engineer, pepper-test-implementer, sage-test-architect, cinnamon-refactor-owl, lavender-interface-designer, parsley-flutter-developer, fennel-go-developer, mint-format-specialist, project-compliance-agent, basil-hook-architect | bypassPermissions + Bash | 可 | ticket append-log + commit + 檔案產出 |
| L2 受限寫入 | thyme-documentation-integrator | acceptEdits + Bash | 可 | ticket append-log + commit + 文件產出 |
| L1 Bash 可寫 | linux, bay-quality-auditor, basil-writing-critic, basil-event-architect, saffron-system-analyst, star-anise-system-designer, incident-responder, oregano-data-miner, ginger-performance-tuner, coriander-integration-tester, clove-security-reviewer, acceptance-auditor, sassafras-data-administrator, sumac-system-engineer | 無 Edit/Write 但有 Bash | 可 | ticket append-log（CLI = Bash）+ Bash heredoc 寫 /tmp 檔 |
| L0 唯讀 | Plan type agent（CC runtime 系統層禁止任何建檔） | 不可 | 不可 | 僅 final message |

關鍵發現：L1 和 L2/L3 在交付能力上差距不大——L1 agent 都有 Bash，可用 heredoc 重導向交付。真正的斷裂點在 L0（Plan type），系統層禁止所有寫入（含 Bash 重導向），交付只剩 final message。

### 交付契約決策

#### 決策結論

| agent 能力 | 交付通道（SSOT） | PM 動作 |
|-----------|-----------------|---------|
| L3/L2（有 Edit/Write） | ticket append-log Solution + commit 產出檔 | 標準驗收（讀 ticket + git log + 測試） |
| L1（有 Bash 無 Edit/Write） | ticket append-log Solution + Bash heredoc 寫 /tmp 檔 | 標準驗收 + Read /tmp 檔 |
| L0（Plan type 唯讀） | final message（唯一通道） | 立即落檔保全（見 fallback SOP） |

#### L0 唯讀型 Fallback SOP（正式化 W2-011 經驗）

觸發條件：PM 以 Plan type 派發 agent，或 agent 因系統層限制無法寫檔。

SOP：
1. 派發前：prompt 明示「報告全文以最終訊息回傳，不嘗試寫檔」
2. 收到 final message 後：PM 立即將 final message 全文寫入 ticket Solution 或 /tmp 檔案
3. 不等待：不假設下次還能取回同樣內容（hook 劫持風險，W2-011 實證）

設計選擇理由：
- 方案 (a) PM 預建結果檔路徑：L0 agent 無法寫入預建檔案，無效
- 方案 (b) ticket CLI 為唯一回傳通道：L0 的 ticket CLI 走 Bash，Plan type Bash 也被禁，無效
- 方案 (c) 唯讀型 PM 收到即落檔：採用，唯一可行方案
- 方案 (d) agent-dispatch-template 加交付通道必填欄位：作為 (c) 配套採用
