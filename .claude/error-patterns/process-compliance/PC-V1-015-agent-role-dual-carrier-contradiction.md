# PC-V1-015: 角色指定雙載體矛盾

## 症狀

- 同一代理人的不同實例對同型任務行為分歧：有的直接實作完成（越界但產出可用），有的讀取自身定義檔後以 needs_context 拒絕執行。
- 派發結果不可預測：PM 依專案入口文件（CLAUDE.md）指定的「實作代理人」派發實作票，代理人卻引用定義檔的「禁止實作」條款停止，acceptance 全數 unmet。
- 定義檔中指名的替補執行代理人屬其他技術棧（模板複製殘留），實際不可用。

## 根因

**同一職責事實存在兩個權威載體且記載相反（雙 SSOT 矛盾）**：

1. 專案入口文件（CLAUDE.md 語言特定規範）指定代理人 X 為實作代理人。
2. 代理人定義檔（.claude/agents/X.md）禁止行為區塊明文禁止 X 實作，並指名由代理人 Y 執行——而 Y 是其他語言專用（定義檔從別的專案模板複製後未同步）。

矛盾的觸發是機率性的：是否爆發取決於該實例是否在執行前讀取並自檢定義檔。未自檢的實例靜默越界（產出可能可用，但職責邊界失效）；自檢的實例正確拒絕（任務停擺）。兩種結果都是損失，且矛盾存在期間每次派發都在擲骰子。

## 解決方案

1. **裁決單一方向**：由用戶/維護者裁決該代理人的真實職責（純規劃 or 可實作），兩載體向同一方向對齊；本次裁決過程與結論記入對應 ticket。
2. **消除專案識別符耦合**：定義檔（框架資產，跨專案同步）不指名其他專案的具體代理人，改指向穩定錨點（「專案指定的執行代理人，指定位置：各專案 CLAUDE.md 語言特定規範章節」）。
3. **前例定位**：矛盾期間越界完成且已驗收的產出不回退（失敗案例學習原則），僅記錄教訓。

## 預防措施

1. **權威分層**：agent 定義檔三區塊（允許產出/禁止行為/適用情境）是職責 SSOT；專案 CLAUDE.md 只做路由（指向哪個代理人），不重複陳述職責內容。兩載體重複陳述同一事實即埋下漂移種子。
2. **派發前查定義檔**：PM 派發實作票前以定義檔三區塊為準核對職責，不以入口文件的一句話指定為準。
3. **模板複製稽核**：從模板或他專案複製 agent 定義檔時，grep 檔內所有代理人名稱，確認指涉對象在本專案 roster 存在且技術棧相符。
4. **同步工具檢查**：框架 sync overlay 場景，同步後執行引用一致性掃描（`grep -rl "<代理人名>" .claude/ CLAUDE.md`）確認職責陳述無矛盾。

## 通用性

任何「入口路由文件 + 個體定義檔」雙層架構皆可重現（CI 設定 vs job 定義、RBAC 政策 vs 角色文件同理）：只要同一職責事實在兩處各自維護，即會因單邊更新而漂移成矛盾，且爆發時機取決於執行端是否自檢，矛盾期間行為不可預測。
